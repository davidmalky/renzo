# TECHNICAL SPECIFICATION: Real-time Sync Execution Engine

## OVERVIEW

A comprehensive real-time synchronization engine that executes field mappings between Salesforce and destination systems. The engine monitors Salesforce changes via CDC and polling, applies transformations, validates data, handles conflicts with configurable strategies, implements retry logic with exponential backoff, and provides detailed logging and monitoring. Built with Node.js/Express backend, PostgreSQL database, Bull queue for job processing, and REST API endpoints for manual triggering and status monitoring.

## VIEWS

- SyncDashboardView: Main monitoring interface displaying active syncs, recent execution history table with status badges, records processed counts, error counts, duration metrics, and quick action buttons to trigger manual syncs or view details. Includes real-time status updates via WebSocket connection showing progress bars for in-flight syncs.

- SyncExecutionDetailView: Detailed view of a single sync execution showing timeline of events, field-by-field change log table with old/new values, error messages with stack traces, conflict resolution decisions, retry attempts visualization, affected record IDs with drill-down capability, and export options for audit reports.

- SyncHistoryView: Paginated table of past sync executions with filters for date range, mapping name, status (success/failed/partial), records processed range. Includes search by record ID or execution ID, sort by any column, bulk operations to retry failed syncs, and CSV export functionality.

- SyncConfigurationView: Configuration panel for polling intervals (dropdown with 5/15/30/60 minute options), conflict resolution strategy selector (radio buttons for source wins/destination wins/manual/timestamp), retry policy settings (max attempts slider, backoff multiplier input), alert threshold configuration (consecutive failures input, email recipient chips), and enable/disable toggle for each mapping.

- ConflictResolutionView: Manual review interface for syncs with manual conflict strategy showing side-by-side comparison of source and destination values, field-level radio selectors to choose winning value, bulk selection options (accept all source/destination), comments textarea for resolution notes, and approve/reject buttons that update sync execution status.

- SyncHealthMonitorView: Real-time health dashboard with status indicators (green/yellow/red) for each active mapping, charts showing sync success rate over time, average execution duration trends, records processed per hour metrics, error rate graphs, alert history table, and system resource usage (queue depth, worker utilization, database connections).

## FUNCTIONS

- pollSalesforceChanges(mappingId, lastPollTimestamp): Queries Salesforce API using SOQL with WHERE LastModifiedDate > lastPollTimestamp filter, retrieves changed records with all mapped fields, handles API pagination using nextRecordsUrl, updates last_poll_timestamp in database, returns array of changed record objects with IDs and field values, catches API rate limit errors and implements backoff, logs polling metrics (records found, API calls made, duration).

- subscribeToCDC(mappingId, objectType): Establishes long-lived connection to Salesforce Change Data Capture API for specified object type, registers event listener for ChangeEventHeader, parses CDC payload to extract record IDs and changed fields, filters events to only include fields in active mappings, pushes change events to sync queue with priority flag, handles reconnection logic on connection drop, maintains cursor position for replay functionality, logs CDC subscription status and event counts.

- executeSync(executionId, mappingId, recordIds): Main sync orchestration function that retrieves mapping configuration from database, fetches source records via Salesforce API, applies field transformations by calling transformation pipeline, validates transformed data against destination schema, detects conflicts by comparing destination current values, applies conflict resolution strategy, writes valid records to destination API, logs all field changes to sync_logs table, updates sync_executions status and metrics, handles partial success scenarios, returns execution summary object.

- applyFieldTransformations(recordData, mappingConfig): Iterates through field mapping rules from mappingConfig, applies transformation type (direct, format, convert, lookup, formula) for each field, calls specific transformer functions (formatString, convertDate, resolveLookup, evaluateFormula), handles null/undefined values per mapping rules, validates transformation output data type, collects transformation errors without stopping pipeline, returns transformed record object with success/error indicators per field.

- formatString(value, formatPattern): Applies string formatting using pattern like "uppercase", "lowercase", "trim", "regex:pattern:replacement", handles null values by returning null or default, validates value is string type, executes regex replacements safely with try-catch, truncates to max length if specified in pattern, returns formatted string or throws ValidationError with details.

- convertDate(value, sourceFormat, targetFormat): Parses date string using sourceFormat specification (ISO8601, MM/DD/YYYY, DD-MM-YYYY, Unix timestamp), converts to Date object with timezone handling, formats to targetFormat using date-fns library, handles timezone conversions if specified in mapping, validates date is valid range (1900-2100), returns formatted date string or throws DateConversionError.

- resolveLookup(value, lookupConfig): Queries lookup table specified in lookupConfig (object type, matching field, return field), searches for record where matching field equals value, handles multiple matches by throwing AmbiguousLookupError, caches lookup results in Redis with 15min TTL, handles lookup failures based on mapping policy (fail sync, use default, skip field), returns resolved value or default, logs cache hit/miss metrics.

- evaluateFormula(formulaExpression, recordContext): Parses formula expression using safe-eval library, extracts field references (${FieldName}), substitutes field values from recordContext object, evaluates mathematical operations (+, -, *, /, %), supports string concatenation and functions (UPPER, LOWER, SUBSTRING, IF), validates result data type matches expected, prevents code injection by whitelisting allowed operations, returns calculated value or throws FormulaEvaluationError with expression details.

- validateAgainstSchema(recordData, schemaRules): Retrieves destination object schema from cache or API, checks required fields are present in recordData, validates data types match schema (string, number, boolean, date), checks string length against maxLength constraint, validates number ranges against min/max, checks picklist values against allowed values, validates date fields are valid dates, validates relationship fields reference existing records, collects all validation errors, returns validation result object with isValid flag and error array.

- detectConflicts(sourceRecord, destinationRecord, mappingConfig): Compares field values between source and destination for mapped fields, identifies fields where values differ, retrieves last modified timestamps for each record, checks if destination was modified since last sync, categorizes conflicts by severity (critical for required fields, warning for optional), applies conflict detection rules from mappingConfig (ignore certain fields, threshold for numeric differences), returns conflict object with differing fields array, timestamps, and severity flags.

- resolveConflict(conflictData, resolutionStrategy): Evaluates resolution strategy (SOURCE_WINS, DESTINATION_WINS, MANUAL_REVIEW, MOST_RECENT_TIMESTAMP), applies strategy to select winning value for each conflicting field, for SOURCE_WINS returns source values, for DESTINATION_WINS returns destination values, for MOST_RECENT_TIMESTAMP compares LastModifiedDate fields, for MANUAL_REVIEW creates pending_review record in database and pauses sync, logs resolution decision with strategy and chosen values, returns resolved record object with winning values and resolution metadata.

- writeToDest ination(recordData, destinationConfig): Constructs API request based on destination type (Salesforce, REST API, Database), handles upsert logic using external ID or primary key, maps field names to destination schema, serializes data to JSON or XML per API requirements, executes HTTP request with authentication headers, handles API rate limiting with retry, parses response to extract created/updated record ID, handles partial success responses, logs API call metrics (duration, payload size, response code), returns write result with success flag and destination record ID.

- queueFailedSync(executionId, recordId, errorDetails): Creates failed_syncs table record with execution_id, record_id, error_message, error_stack, retry_count (0), next_retry_at (calculated with exponential backoff), original_payload JSON, publishes message to retry queue with delay, updates sync_executions error_count counter, checks if error is retryable (network errors yes, validation errors no), categorizes error type for monitoring, returns queue entry ID.

- retryFailedSync(failedSyncId): Retrieves failed sync record from database, checks retry_count against max_retries (3), calculates backoff delay (2^retry_count * 60 seconds), increments retry_count, updates next_retry_at timestamp, calls executeSync with original payload, if success removes from failed_syncs table, if failure updates record with new error_details, if max retries exceeded marks as permanently failed and triggers alert, logs retry attempt outcome.

- calculateExponentialBackoff(retryCount, baseDelaySeconds): Computes delay as baseDelaySeconds * (2 ** retryCount), adds random jitter (0-20% of delay) to prevent thundering herd, caps maximum delay at 1 hour, validates retryCount is non-negative integer, returns delay in milliseconds for queue scheduling.

- createSyncLog(executionId, recordId, fieldName, oldValue, newValue, errorMessage): Inserts record into sync_logs table with all parameters, timestamps with current UTC time, serializes old/new values to JSON strings if objects, truncates error messages to 5000 characters, generates unique log ID, indexes by execution_id and record_id for fast queries, returns log entry ID, handles database errors by logging to file fallback.

- getSyncStatus(syncId): Queries sync_executions table by id, retrieves current status (queued, running, completed, failed, paused), calculates progress percentage (records_processed / total_records), estimates completion time based on current rate, fetches recent log entries for display, checks for pending conflicts requiring manual review, returns status object with all metrics and metadata, caches result for 5 seconds to reduce database load.

- getSyncHistory(filters, pagination): Builds SQL query with WHERE clauses for filter parameters (startDate, endDate, mappingId, status), applies LIMIT and OFFSET for pagination, orders by started_at DESC, joins with mappings table to include mapping name, calculates aggregate metrics (total records, total errors, average duration), counts total matching records for pagination metadata, returns history array and pagination object (currentPage, totalPages, totalCount).

- triggerManualSync(mappingId, recordIds): Validates mapping exists and is active, creates new sync_executions record with status 'queued', generates unique execution ID, publishes job to sync queue with high priority, optionally filters to specific recordIds if provided, updates mapping last_triggered_at timestamp, returns execution ID for status polling, logs manual trigger event with user ID, handles concurrent trigger requests with database lock.

- startBackgroundWorker(): Initializes Bull queue connection to Redis, registers job processor function for 'sync-execution' jobs, sets concurrency limit (5 parallel jobs), configures job retry policy, starts polling worker that checks for due scheduled syncs, subscribes to CDC events if enabled, registers cleanup handlers for graceful shutdown, monitors queue health and logs metrics every 60 seconds, handles worker errors and restarts.

- processSyncJob(job): Extracts job data (executionId, mappingId, recordIds), updates execution status to 'running', calls executeSync function, handles success by updating status to 'completed', handles errors by updating status to 'failed' and queueing retry, calculates and stores execution metrics, emits progress events to WebSocket clients, cleans up temporary resources, returns job result object.

- monitorSyncHealth(): Runs every 5 minutes to check sync health, queries for failed executions in last hour, counts consecutive failures per mapping, triggers alert if threshold exceeded (3 consecutive failures), checks queue depth and alerts if over 1000 jobs, monitors worker heartbeat and restarts if stalled, tracks success rate by mapping and flags degradations, posts metrics to monitoring service, logs health check results.

- sendSyncAlert(mappingId, alertType, alertData): Retrieves alert configuration for mapping, formats alert message with alertType and alertData details, sends email via SMTP to configured recipients, posts to Slack webhook if configured, creates alert record in database for history, throttles duplicate alerts (max 1 per mapping per 15min), logs alert delivery status, returns alert ID.

- cleanupOldLogs(retentionDays): Calculates cutoff date (retentionDays ago), deletes sync_logs older than cutoff in batches (10000 records at a time), deletes completed sync_executions older than cutoff, vacuum analyzes database tables after delete, logs cleanup metrics (records deleted, space freed), runs as scheduled job at 2am daily, handles cleanup errors gracefully.

- getAPIRateLimits(): Queries Salesforce API for current rate limit status, parses response headers (Sforce-Limit-Info), calculates remaining API calls and reset time, stores in Redis cache with TTL until reset, returns rate limit object with remaining and resetAt fields, used by polling functions to throttle requests.

- handleAPIRateLimitError(error): Detects rate limit error from API response (429 status), extracts Retry-After header value, calculates delay until API calls available, pauses sync execution for delay period, publishes job back to queue with delay, logs rate limit event with wait time, updates monitoring metrics, throws RateLimitError to fail job gracefully.

- getDestinationSchema(objectType): Checks Redis cache for schema with key "schema:{objectType}", if cache miss calls destination API describe endpoint, parses API response to extract field definitions (name, type, required, maxLength, picklist values), stores in cache with 1 hour TTL, handles API errors by using last known schema, returns schema object with fields array.

- validateConnectionHealth(mappingId): Retrieves mapping configuration including source and destination connection details, tests Salesforce connection by calling simple query, tests destination connection by calling health endpoint, measures response times, validates credentials still valid, returns health object with status and latency for each connection, called before executing sync to fail fast on connection issues.

- pauseSyncExecution(executionId, reason): Updates sync_executions status to 'paused', stores pause reason in notes field, removes job from processing queue if running, saves current progress (records processed), logs pause event with reason and user, allows manual conflict resolution or system maintenance, returns success confirmation.

- resumeSyncExecution(executionId): Validates execution is in paused state, retrieves saved progress and remaining records, creates new job with remaining records only, publishes to high priority queue, updates status to 'queued', logs resume event, returns new job ID.

- exportSyncReport(executionId, format): Retrieves execution record and all related logs, formats data based on format parameter (CSV, JSON, PDF), for CSV creates rows with execution summary and detail log rows, applies column headers, streams to file or HTTP response, includes metadata (execution time, user, mapping name), compresses large reports, returns file path or stream, handles memory efficiently for large datasets.

- calculateSyncMetrics(executionId): Aggregates sync_logs for execution, counts total records processed, successful updates, failed records, conflict resolutions, calculates processing rate (records/second), average field transformation time, identifies slowest fields, finds most common error types, returns metrics object for storage and display.

- getBatchRecordIds(mappingId, batchSize): Queries Salesforce for record IDs modified since last sync, limits results to batchSize (default 1000), applies mapping field filters to WHERE clause, orders by LastModifiedDate ASC to process oldest changes first, handles API pagination, returns array of record ID strings, updates sync cursor after successful retrieval.

- handlePartialSyncSuccess(executionId, successRecords, failedRecords): Updates execution status to 'partial-success', stores count of successful and failed records, creates failed_sync entries for each failed record individually, calculates success percentage, triggers warning alert if failure rate exceeds 10%, commits successful record changes, prepares failed records for retry, logs partial completion with details.

- serializeRecordForQueue(recordData, mappingConfig): Converts record object to JSON string for queue storage, redacts sensitive fields per data policy, compresses large payloads using gzip, includes mapping metadata for job processing, adds checksum for integrity validation, limits payload size to 256KB, throws error if record too large, returns serialized string.

- deserializeRecordFromQueue(payload): Decompresses gzipped payload if compressed flag set, parses JSON string to object, validates checksum matches, hydrates record with type information, handles legacy payload formats for backward compatibility, throws error on corruption, returns record object.

- lockMappingForSync(mappingId): Acquires PostgreSQL advisory lock for mapping row, prevents concurrent syncs of same mapping, sets lock timeout to 5 seconds, throws error if lock unavailable, stores lock acquisition time for monitoring, automatically releases on transaction commit, handles deadlocks gracefully.

- unlockMapping(mappingId): Releases advisory lock on mapping row, updates mapping last_synced_at timestamp, clears in-progress flag, logs lock duration, handles unlock errors, ensures cleanup in finally block.

- trackSyncProgress(executionId, recordsProcessed, totalRecords): Updates sync_executions records_processed counter, calculates progress percentage, estimates time remaining based on current rate, emits WebSocket event to connected clients with progress update, updates every 100 records to avoid excessive updates, stores last_updated_at timestamp, handles race conditions with atomic updates.

## DATA

- sync_executions: Table storing execution records with columns id (UUID primary key), mapping_id (UUID foreign key to mappings table), status (enum: queued, running, completed, failed, paused, partial-success), started_at (timestamp with timezone), completed_at (timestamp with timezone, nullable), records_processed (integer default 0), total_records (integer), errors_count (integer default 0), success_rate (decimal calculated field), duration_seconds (integer), triggered_by (enum: scheduled, manual, cdc, api), triggered_by_user_id (UUID nullable), notes (text for pause reasons or errors), created_at (timestamp), indexes on (mapping_id, started_at), (status, started_at), (triggered_by_user_id).

- sync_logs: Detailed field-level change logs with columns id (bigint serial primary key), execution_id (UUID foreign key to sync_executions), record_id (varchar 18 for Salesforce ID), record_type (varchar for object type), field_name (varchar), old_value (jsonb nullable), new_value (jsonb nullable), transformation_applied (varchar nullable describing transformation), error_message (text nullable), error_code (varchar nullable), error_stack (text nullable), conflict_detected (boolean default false), conflict_resolution (enum: source_wins, destination_wins, manual, skipped, nullable), timestamp (timestamp with timezone default now), processing_time_ms (integer), indexes on (execution_id, timestamp), (record_id), (error_message IS NOT NULL), (conflict_detected), partitioned by range on timestamp (monthly partitions for performance).

- failed_syncs: Retry queue table with columns id (UUID primary key), execution_id (UUID foreign key), record_id (varchar 18), error_message (text), error_code (varchar), error_stack (text), retry_count (integer default 0), max_retries (integer default 3), next_retry_at (timestamp with timezone), original_payload (jsonb with record data and mapping config), is_retryable (boolean), permanently_failed (boolean default false), created_at (timestamp), last_retry_at (timestamp nullable), indexes on (next_retry_at, permanently_failed), (execution_id), (retry_count).

- mapping_configurations: Extended mapping config with columns id (UUID primary key), name (varchar), source_connection_id (UUID), destination_connection_id (UUID), source_object (varchar), destination_object (varchar), sync_direction (enum: source_to_dest, dest_to_source, bidirectional), polling_interval_minutes (integer default 15, check constraint in (5, 15, 30, 60)), conflict_resolution_strategy (enum: source_wins, destination_wins, manual_review, most_recent_timestamp), is_active (boolean default true), enable_cdc (boolean default false), last_poll_timestamp (timestamp with timezone), last_synced_at (timestamp with timezone), field_mappings (jsonb array of mapping rules), transformation_rules (jsonb with transformation configs), validation_rules (jsonb with schema rules), retry_policy (jsonb with max_retries and backoff_multiplier), alert_config (jsonb with recipients and thresholds), created_by (UUID), created_at (timestamp), updated_at (timestamp), indexes on (is_active, polling_interval_minutes), (last_poll_timestamp), (source_object), (destination_object).

- field_mapping_rules: Normalized field mappings with columns id (UUID primary key), mapping_id (UUID foreign key to mapping_configurations), source_field (varchar), destination_field (varchar), transformation_type (enum: direct, format_string, convert_date, resolve_lookup, evaluate_formula, custom), transformation_config (jsonb with type-specific parameters), is_required (boolean), default_value (varchar nullable), validation_rules (jsonb array of validation objects), sync_direction (enum: left, right, bidirectional), is_active (boolean), sort_order (integer for display), indexes on (mapping_id, is_active).

- sync_conflicts: Manual review queue with columns id (UUID primary key), execution_id (UUID foreign key), record_id (varchar 18), record_type (varchar), conflict_fields (jsonb array with field name, source value, dest value), detected_at (timestamp with timezone default now), resolved_at (timestamp with timezone nullable), resolved_by (UUID nullable), resolution_decision (jsonb with field-level choices), resolution_notes (text), status (enum: pending, resolved, skipped), assigned_to (UUID nullable for workflow), indexes on (status, detected_at), (execution_id), (assigned_to).

- sync_health_metrics: Monitoring data with columns id (UUID primary key), mapping_id (UUID foreign key), check_timestamp (timestamp with timezone default now), queue_depth (integer), active_workers (integer), success_rate_1h (decimal), success_rate_24h (decimal), average_duration_seconds (decimal), records_per_hour (decimal), error_rate (decimal), consecutive_failures (integer), api_rate_limit_remaining (integer), last_successful_sync_at (timestamp with timezone), alerts_triggered (integer), is_healthy (boolean computed field), indexes on (mapping_id, check_timestamp), (is_healthy, check_timestamp), partitioned by range on check_timestamp (daily partitions).

- alert_history: Alert tracking with columns id (UUID primary key), mapping_id (UUID foreign key), alert_type (enum: consecutive_failures, high_error_rate, queue_overload, worker_stalled, api_rate_limit, validation_failures), alert_severity (enum: warning, error, critical), alert_message (text), alert_data (jsonb with contextual details), triggered_at (timestamp with timezone default now), acknowledged_at (timestamp with timezone nullable), acknowledged_by (UUID nullable), notification_sent (boolean default false), notification_channels (varchar array with email, slack, pagerduty), indexes on (mapping_id, triggered_at), (alert_type, alert_severity), (acknowledged_at IS NULL).

- sync_cursors: CDC and polling position tracking with columns id (UUID primary key), mapping_id (UUID foreign key unique), source_object (varchar), cursor_type (enum: timestamp, cdc_replay, offset), cursor_value (varchar for timestamp or replay ID), last_updated_at (timestamp with timezone default now), records_since_cursor (integer counter), is_valid (boolean default true), indexes on (mapping_id), (source_object, cursor_type).

- api_rate_limits: Rate limit caching with columns id (UUID primary key), connection_id (UUID), api_type (varchar like 'salesforce', 'rest_api'), limit_type (varchar like 'daily', 'per_second'), total_limit (integer), remaining (integer), reset_at (timestamp with timezone), measured_at (timestamp with timezone default now), indexes on (connection_id, api_type), (reset_at), TTL of 1 hour.

- transformation_cache: Lookup and computed value caching with columns cache_key (varchar primary key), cache_value (jsonb), transformation_type (varchar), source_mapping_id (UUID), created_at (timestamp with timezone default now), expires_at (timestamp with timezone), hit_count (integer default 0), indexes on (expires_at), (source_mapping_id), background job cleans expired entries.

- worker_heartbeats: Worker health tracking with columns worker_id (varchar primary key), worker_type (enum: sync_processor, retry_handler, cdc_listener, poller), started_at (timestamp with timezone), last_heartbeat_at (timestamp with timezone default now), current_job_id (UUID nullable), jobs_processed (integer default 0), jobs_failed (integer default 0), is_active (boolean default true), host_name (varchar), process_id (integer), indexes on (is_active, last_heartbeat_at), stale workers detected if last_heartbeat_at > 5 minutes ago.

- queue_jobs: Job queue state mirroring Bull queue with columns job_id (varchar primary key from Bull), job_type (enum: sync_execution, retry_failed_sync, manual_conflict_resolution), job_data (jsonb with execution details), priority (integer), status (enum:
