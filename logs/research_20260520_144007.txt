## RISKS:
- **API rate limiting**: Batch generation could hit OpenAI API rate limits if processing many contacts simultaneously. Implement sequential processing with progress tracking instead of parallel requests
- **localStorage quota**: Multiple rules and large contact lists could approach localStorage 5-10MB limit. Monitor but unlikely to be immediate issue
- **Prompt injection vulnerability**: User-provided rules get injected into AI prompts. Could lead to prompt injection attacks. Mitigate by treating rules as plaintext instructions, not executable code
- **Keyword matching ambiguity**: Simple keyword matching (e.g., "contract" matching both contractExpiry and general notes text) may produce false positives. Keep matching specific to field names only
- **Existing AI message flow disruption**: Modifying `generateAiMessage()` could break existing single-contact generation if rules parameter is not optional/backward compatible
- **Navigation state conflicts**: Adding new view could conflict with existing view state management if not following exact same pattern
- **Rule deletion index errors**: Deleting rules by array index requires careful state management to avoid deleting wrong rule
- **Empty rules array handling**: Must handle case where 'renzo_rules' is null, undefined, or empty array when appending to prompts

### Contact field mappings for keyword filtering:
- Keywords: "contract", "expiry", "expire", "expiring" → Check `contact.contractExpiry` field (ISO date string)
- Keywords: "invoice", "overdue", "payment" → Check `contact.invoiceAmount` field (numeric string)
- Keywords: "not contacted", "never contacted", "no contact", "overdue contact" → Check `contact.lastContactDate` field (ISO date string or empty)

### Batch outreach data flow:
1. User enters natural language query in textarea
2. Parse query for keywords (case-insensitive matching)
3. Filter contacts array based on matched field + value logic
4. For each filtered contact, call `generateAiMessage(contact)` sequentially
5. Add each generated message to outreach queue (existing queue structure)
6. Display progress: "Generating {current} of {total}..."
7. Show summary: "{count} messages added to outreach queue"
