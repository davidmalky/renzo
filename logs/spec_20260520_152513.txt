# TECHNICAL SPECIFICATION: BATCH OUTREACH & TRAINABLE INSTRUCTIONS

## OVERVIEW
Add batch outreach capability allowing natural language queries to filter contacts and generate AI messages in bulk. Add trainable instructions system in Settings allowing users to define custom outreach rules that append to all AI prompts. Both features integrate surgically into existing Renzo codebase without modifying core contact/queue infrastructure.

## FUNCTIONS

**executeBatchOutreach(query)**
1. Validate query is not empty, show alert if empty, return
2. Parse query keywords: check for "contract" OR "expiry" (use contractExpiry field), "invoice" (use invoiceAmount field), "contacted" (use lastContactDate field)
3. Get contacts from localStorage key 'renzo_contacts', parse JSON
4. Filter contacts: for each contact, apply keyword-based filters:
   - If query contains "contract"/"expiry": filter contractExpiry field (check if date within extracted days or exists)
   - If query contains "invoice": filter invoiceAmount (check if amount > extracted number)
   - If query contains "contacted": filter lastContactDate (check if date older than extracted days)
5. Show `.batch-progress` div, hide results
6. Initialize progress counter: processedCount = 0, totalCount = filteredContacts.length
7. For each filtered contact:
   - Call generateAiMessage(contact) with modified prompt including rules
   - Create queue item object: {contactId, contactName, message, status: 'pending', date: ISO string}
   - Add to queue in localStorage key 'renzo_queue'
   - Increment processedCount, update progress bar width % and status text
   - Use setTimeout for async simulation (50ms delay per contact)
8. On completion: hide progress, show `.batch-results` with count summary
9. Render results list with contact names and message previews
10. Trigger queue view refresh if active

**addOutreachRule()**
1. Get value from `.rule-input` textarea, trim whitespace
2. If empty, show alert "Please enter a rule", return
3. Load existing rules from loadRules()
4. Add new rule to array: rules.push({id: Date.now(), text: ruleText})
5. Save to localStorage key 'renzo_rules' as JSON string
6. Clear textarea input
7. Call renderRules() to update display
8. Show success alert "Rule added successfully"

**deleteOutreachRule(ruleId)**
1. Load rules from loadRules()
2. Filter rules array to remove rule with matching id
3. Save updated array to localStorage 'renzo_rules'
4. Call renderRules() to update display

**loadRules()**
1. Get localStorage item 'renzo_rules'
2. If null/undefined, return empty array []
3. Parse JSON and return array of rule objects

**renderRules()**
1. Get rules from loadRules()
2. Select `.rules-list` element
3. If rules.length === 0, set innerHTML to empty state message
4. Else, map rules to HTML: for each rule create `.rule-item` with `.rule-text` (escaped) and delete button with data-rule-id attribute
5. Set innerHTML of `.rules-list`
6. Attach click event listeners to all delete buttons calling deleteOutreachRule(ruleId)

**getAiPromptWithRules(basePrompt)**
1. Load rules from loadRules()
2. If rules.length === 0, return basePrompt unchanged
3. Create rules text: "Additional instructions: " + rules.map(r => r.text).join('. ') + '.'
4. Return basePrompt + '\n\n' + rulesText

**Modified: generateAiMessage(contact)** (existing function modification)
1. Before making API call, wrap original prompt generation in getAiPromptWithRules()
2. Existing logic remains unchanged, only prompt is enhanced

**initializeBatchOutreach()**
1. Attach click listener to "Generate Batch Messages" button calling executeBatchOutreach() with textarea value
2. Initialize view state

**initializeTrainableRules()**
1. Call renderRules() to load initial display
2. Attach click listener to "Add Rule" button calling addOutreachRule()
3. Initialize event delegation for delete buttons

## DATA

**localStorage: 'renzo_rules'**
- Format: JSON string array of objects
- Structure: `[{id: number, text: string}, ...]`
- Example: `[{id: 1703001234567, text: "Always mention ROI in first sentence"}, {id: 1703001234890, text: "Keep messages under 100 words"}]`

**localStorage: 'renzo_queue'** (existing, modified)
- Batch items added with same structure as manual queue items
- Each item: `{contactId: string, contactName: string, message: string, status: string, date: string, batchId: string (optional)}`

**localStorage: 'renzo_contacts'** (existing, read-only)
- Read for filtering in batch operations
- Expected fields: contractExpiry, invoiceAmount, lastContactDate, name, id

**Session state: batchProgress**
- In-memory object tracking current batch execution
- Properties: {total: number, processed: number, isRunning: boolean}

## ERRORS

**Empty Query Error**
- Trigger: executeBatchOutreach() called with empty/whitespace-only query
- Display: `.alert.alert-error` with message "Please enter a search query to filter contacts"
- Position: above batch input card
- Auto-dismiss: after 4 seconds

**No Contacts Match Error**
- Trigger: filtered contacts array length === 0 after applying filters
- Display: `.alert.alert-warning` with message "No contacts match your search criteria. Try a different query."
- Position: in `.batch-results` area
- Persistent until new query

**Empty Rule Error**
- Trigger: addOutreachRule() called with empty textarea
- Display: `.alert.alert-error` with message "Please enter a rule before adding"
- Position: above rules input card
- Auto-dismiss: after 3 seconds

**API Failure During Batch**
- Trigger: generateAiMessage() returns error for any contact
- Action: mark that contact as failed in results, continue with remaining contacts
- Display: show failed count in batch results summary, mark failed items with `.status-failed` badge
- No halt: batch continues processing remaining contacts

**LocalStorage Quota Exceeded**
- Trigger: saving rules or queue items exceeds storage limit
- Display: `.alert.alert-error` with message "Storage limit reached. Please delete old messages or rules."
- Position: top of active view
- Action: revert last operation, notify user

**Invalid Contact Data**
- Trigger: contact object missing expected fields during filtering
- Action: skip contact, log warning to console
- No user-facing error (silently exclude malformed contacts)
