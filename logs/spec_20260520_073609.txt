# TECHNICAL SPECIFICATION: Real-time Sync Execution Engine

## OVERVIEW
A production-grade synchronization engine that polls Salesforce for data changes, applies field transformations and validations, handles bidirectional sync conflicts with configurable strategies, implements retry logic with exponential backoff, maintains detailed audit logs, and exposes REST APIs for manual triggering and monitoring. The system uses a background worker architecture with job queues, database-backed state management, and health monitoring with alerting for repeated failures.

## VIEWS

- SyncDashboardView: Real-time monitoring interface showing active syncs, success/failure metrics, recent activity feed, health status indicators, and quick action buttons for manual sync triggers. Displays 5 stat cards (active syncs, queued jobs, success rate 24h, failed last hour, avg sync time) and live activity table with auto-refresh every 10 seconds.

- SyncHistoryView: Paginated table of sync executions with filters (date range, status, mapping name), sortable columns (started_at, duration, records processed, errors), expandable row details showing field-level changes, search bar for record IDs, and export to CSV button. Displays 50 records per page with infinite scroll option.

- SyncExecutionDetailView: Drill-down view for individual sync execution showing timeline visualization, record-level processing status, error details with stack traces, conflict resolution log, retry attempt history, performance metrics (records/sec, API calls made), and detailed field transformation audit trail. Includes "Retry Failed Records" and "Download Full Log" buttons.

- SyncHealthMonitorView: System health dashboard with uptime metrics, error rate trends (line chart last 24h), bottleneck identification (slow transformations, API rate limits), alert configuration panel, and notification history. Shows color-coded status indicators (green: healthy, yellow: degraded, red: critical).

- ConflictResolutionView: Queue of records requiring manual conflict resolution with side-by-side diff view, field-level comparison highlighting changed values, metadata display (last modified by, timestamp), resolution action buttons (Accept Source, Accept Destination, Custom Merge), and bulk resolution options for similar conflicts.

- SyncConfigurationView: Form interface for configuring sync parameters including polling interval dropdown (5/15/30/60 min), conflict resolution strategy selector (radio buttons), retry policy settings (max retries, backoff multiplier), batch size input, parallel worker count, API rate limit thresholds, and timeout configurations. Includes "Test Connection" and "Save Configuration" buttons.

## FUNCTIONS

- startSyncExecution(mappingId, triggeredBy, isManual): Creates new sync_executions record with status 'pending', validates mapping configuration exists and is active, checks for already-running sync on same mapping (throws error if found), enqueues sync job to worker queue with priority (manual=high, scheduled=normal), publishes 'sync.started' event to websocket, records audit log entry, returns execution ID and estimated start time.

- pollSalesforceChanges(mappingId, lastSyncTimestamp): Queries Salesforce API using SOQL with WHERE LastModifiedDate > lastSyncTimestamp filter, handles pagination with LIMIT 2000 and OFFSET, extracts configured source fields from mapping definition, builds change set array with record IDs and field values, stores raw API response in sync_api_logs table, updates last_poll_timestamp in sync_state table, returns array of changed records with metadata (id, fields, lastModifiedDate, isDeleted flag).

- subscribeToCDC(mappingId, objectName): Establishes streaming API connection to Salesforce Change Data Capture channel for specified object, registers event listener callback, handles authentication token refresh, implements reconnection logic with exponential backoff (1s, 2s, 4s, 8s, max 60s), processes incoming events and converts to internal change format, enqueues change records to sync queue, logs CDC errors to monitoring system, maintains connection state in memory with heartbeat every 30 seconds.

- applyFieldTransformations(sourceRecord, mappingConfig): Iterates through field mapping rules in mappingConfig.fieldMappings array, extracts source field value using dot notation path resolver, determines transformation type (direct, formula, lookup, date_conversion, string_format), calls appropriate transformation function, validates output data type matches destination schema, handles null values per null_handling rule (skip, default_value, error), collects transformation errors without stopping execution, returns transformed record object with success flag and error array.

- transformDirectCopy(sourceValue, transformConfig): Returns sourceValue unchanged if not null, applies type coercion if destination type differs (string to number, date string to ISO format), validates value length for string destinations (max_length check), trims whitespace if trim_whitespace flag true, returns transformed value or null.

- transformStringFormat(sourceValue, transformConfig): Applies format template from transformConfig.template using placeholder replacement (e.g., "{firstName} {lastName}"), handles nested field references, applies string functions (uppercase, lowercase, capitalize, substring), validates result length against max_length, escapes special characters if escape_html flag true, returns formatted string.

- transformDateConversion(sourceValue, transformConfig): Parses source date using transformConfig.sourceFormat (ISO8601, MM/DD/YYYY, YYYY-MM-DD, Unix timestamp), converts to Date object with timezone consideration, formats to destination format using transformConfig.destinationFormat, handles timezone conversion using transformConfig.sourceTimezone and destinationTimezone, validates date range if min_date/max_date specified, returns formatted date string or throws parsing error.

- transformLookupResolution(sourceValue, transformConfig): Queries lookup cache using transformConfig.lookupTable and sourceValue as key, if cache miss queries destination database table with WHERE clause, performs JOIN if relationship_field specified, extracts transformConfig.returnField from result, stores result in lookup cache with TTL (default 300s), handles lookup failures per transformConfig.onMissingLookup (error, skip, default_value), returns resolved value or null.

- transformFormulaCalculation(sourceRecord, transformConfig): Parses formula expression from transformConfig.formula using expression evaluator, extracts variable references (e.g., ${field_name}), substitutes values from sourceRecord, evaluates mathematical operations (+, -, *, /, %, ^), applies functions (SUM, AVG, MAX, MIN, ROUND, IF, CONCAT), handles operator precedence and parentheses, validates result type matches expected return type, catches evaluation errors and wraps in user-friendly message, returns calculated value.

- validateAgainstSchema(transformedRecord, destinationSchema): Iterates through destinationSchema.fields array, checks required fields present in transformedRecord, validates data types match (string, number, boolean, date, array, object), enforces string length constraints (minLength, maxLength), validates number ranges (minimum, maximum), applies regex pattern validation if pattern specified, checks enum values if restricted list defined, validates array item constraints (minItems, maxItems, uniqueItems), collects all validation errors with field path and error message, returns validation result object with isValid flag and errors array.

- detectSyncConflict(sourceRecord, destinationRecord, mappingConfig): Compares LastModifiedDate timestamps from both records, identifies fields with differing values, retrieves previous sync state from sync_state table using record_id, determines if changes occurred on both sides since last sync, applies conflict detection rules from mappingConfig.conflictDetection (ignore_readonly_fields, field_priority_list), creates conflict object with field-level details (source_value, destination_value, last_synced_value, modified_timestamps), returns conflict object or null if no conflict detected.

- resolveConflictAutomatically(conflict, resolutionStrategy): Evaluates resolutionStrategy type (source_wins, destination_wins, most_recent, field_priority), applies strategy logic to select winning value for each conflicting field, if most_recent compares modified timestamps, if field_priority checks priority list order, handles tie-breaking with default to source, creates resolution log entry with strategy used and selected values, updates conflict status to 'auto_resolved', returns resolved record with metadata indicating resolution method.

- queueForManualResolution(conflict, executionId): Inserts record into manual_resolution_queue table with conflict details JSON, sets priority based on business criticality from mapping config, creates notification for sync admin users, increments pending_conflicts counter for execution, sets conflict status to 'pending_manual', publishes 'conflict.manual_required' event, returns queue item ID and estimated resolution time based on queue depth.

- validateDataIntegrity(sourceRecord, destinationRecord, validationRules): Executes custom validation rules from validationRules array, checks referential integrity (foreign key exists in related table), validates business logic constraints (e.g., end_date > start_date), runs cross-field validation rules, verifies required relationships exist, checks for circular dependencies, validates uniqueness constraints against destination database, collects integrity errors with severity levels (error, warning), returns validation result with blocking errors and non-blocking warnings.

- executeSyncWrite(transformedRecord, destinationConfig, executionId): Begins database transaction, locks destination record for update if exists (SELECT FOR UPDATE), performs upsert operation using natural key from destinationConfig.uniqueKey, updates all mapped fields with transformed values, sets last_synced_at timestamp, increments sync_version counter, logs old and new values to sync_logs table, commits transaction, handles deadlock with retry (max 3 attempts), publishes 'record.synced' event with record ID, updates records_processed counter for execution, returns write result with success flag and destination record ID.

- handleSyncFailure(executionId, recordId, error, retryCount): Logs error details to sync_errors table with full stack trace, categorizes error type (validation, transformation, network, api_limit, database), determines if error is retriable (network timeout, rate limit, temporary db issue), if retriable and retryCount < 3 enqueues retry job with exponential backoff delay (60s * 2^retryCount), if not retriable marks record as failed permanently, sends error notification if critical, updates execution error_count, creates error metrics for monitoring, returns retry decision and next retry timestamp.

- calculateBackoffDelay(retryCount, baseDelay): Computes exponential backoff as baseDelay * (2 ^ retryCount), applies jitter randomization (±20%) to prevent thundering herd, caps maximum delay at 900 seconds (15 minutes), adjusts for retry priority (manual syncs have lower max delay), returns delay in milliseconds for queue scheduling.

- processRetryQueue(): Scans retry_queue table for jobs with next_retry_at <= NOW(), orders by priority and next_retry_at, processes batch of 100 jobs, extracts original sync parameters, calls startSyncExecution with retry flag, marks queue items as processing, handles processing failures by requeing, removes successful retries from queue, updates retry metrics, sleeps for 10 seconds before next scan.

- createSyncLog(executionId, recordId, fieldName, oldValue, newValue, logType): Inserts record into sync_logs table with timestamp, execution_id, record_id, field_name, serializes old_value and new_value to JSON, sets log_type (insert, update, delete, conflict, error, transformation), stores user_id if manual action, compresses large values (>1KB) with gzip flag, batches log inserts for performance (flush every 100 logs), returns log entry ID.

- getSyncStatus(syncId): Queries sync_executions table by syncId, calculates progress percentage (records_processed / total_records * 100), retrieves current status (pending, running, completed, failed, paused), fetches recent log entries (last 10), computes estimated completion time based on processing rate, includes error summary (count by error type), checks for conflicts requiring manual resolution, returns status object with nested details.

- getSyncHistory(filters, pagination): Builds SQL query for sync_executions table with WHERE clauses from filters (date_range, status, mapping_id, triggered_by), applies pagination (OFFSET and LIMIT from pagination.page and pagination.pageSize), orders by started_at DESC, performs JOIN with mappings table for mapping name, aggregates error counts from sync_errors, calculates duration (completed_at - started_at), formats timestamps to ISO8601, returns paginated result with total count and page metadata.

- getExecutionDetails(executionId): Queries sync_executions with all columns, fetches related sync_logs with pagination (first 1000 records), retrieves sync_errors with full error details, loads conflict_resolutions for this execution, calculates performance metrics (records per second, API calls per record), builds timeline array with key events (started, first_record, errors_occurred, conflicts_detected, completed), includes retry history from retry_queue, returns comprehensive execution details object.

- monitorSyncHealth(): Queries sync_executions for last 24 hours, calculates success rate (completed / total * 100), identifies executions with high error rates (>10% failed records), detects repeated failures (same mapping failed 3+ times in 6 hours), checks for stalled syncs (running > 2 hours), monitors queue depth in retry_queue and manual_resolution_queue, evaluates API rate limit remaining from last poll, computes average sync duration per mapping, identifies slow transformations from log analysis, returns health report object with status (healthy, degraded, critical) and issues array.

- triggerHealthAlert(healthIssue): Evaluates alert rules for issue type and severity, checks alert throttling (don't send duplicate within 1 hour), formats alert message with issue details and recommended actions, sends notifications via configured channels (email, Slack webhook, PagerDuty), logs alert to alert_history table, updates alert metrics, creates incident ticket if severity is critical, returns alert ID and delivery status.

- cleanupOldLogs(retentionDays): Calculates cutoff date (NOW() - retentionDays), deletes sync_logs older than cutoff in batches of 10000, archives logs to cold storage before deletion if archiving enabled, updates retention metrics, vacuums database tables to reclaim space, logs cleanup summary (records deleted, space freed), returns cleanup result with rows affected.

- exportSyncReport(executionId, format): Retrieves full execution details using getExecutionDetails, formats data according to format parameter (json, csv, xlsx), for CSV flattens nested objects and creates multiple sheets, includes summary statistics in header, generates downloadable file with timestamp in filename, stores temporarily in reports storage (S3 or filesystem), creates download token with 1-hour expiration, returns download URL and file metadata.

- pauseSyncExecution(executionId, userId): Validates execution is in 'running' status, sets pause_requested flag in sync_executions, worker checks flag and stops processing new records, completes in-flight records, updates status to 'paused' and records paused_at timestamp, logs pause action with userId, publishes 'sync.paused' event, returns confirmation with records processed before pause.

- resumeSyncExecution(executionId, userId): Validates execution is in 'paused' status, updates status back to 'running' and clears paused_at, requeues remaining records for processing, worker resumes from last processed record, logs resume action with userId, publishes 'sync.resumed' event, returns confirmation with remaining record count.

- cancelSyncExecution(executionId, userId, reason): Validates execution is in 'running' or 'paused' status, sets cancellation_requested flag, worker stops immediately after current record, rolls back in-flight transactions, updates status to 'cancelled', records cancelled_at, cancelled_by, cancellation_reason, cleans up any queued jobs for this execution, logs cancellation action, publishes 'sync.cancelled' event, returns cancellation confirmation.

- optimizeSyncPerformance(mappingId): Analyzes historical execution data for mapping, identifies bottlenecks (slow transformations, API latency, database writes), recommends batch size adjustments, suggests field mapping optimizations, evaluates parallel worker scaling, checks for missing database indexes, validates lookup cache effectiveness, generates optimization report with actionable recommendations, updates performance_tuning table with suggestions, returns optimization recommendations array.

- loadMappingConfiguration(mappingId): Queries mappings table by mappingId, validates mapping is active (status = 'active'), loads related field_mappings with transformations and validations, retrieves conflict resolution strategy, fetches polling interval and batch size settings, loads source and destination connection credentials (decrypts secrets), validates all referenced lookup tables exist, caches configuration in memory with TTL (600s), returns complete mapping configuration object.

- validateAPIConnection(connectionConfig): Tests connection to Salesforce API using credentials from connectionConfig, performs authentication (OAuth 2.0 client credentials or JWT), validates API version compatibility, checks required API permissions (Read, Write, ChangeDataCapture), tests query execution with simple SOQL, measures response time, verifies rate limits and quota remaining, logs connection test result, returns connection status with error details if failed.

- updateSyncState(mappingId, recordId, syncMetadata): Upserts record into sync_state table using composite key (mapping_id, record_id), stores last_synced_at timestamp, saves checksum of synced field values for conflict detection, records sync_version counter, stores source_last_modified and destination_last_modified timestamps, maintains bidirectional sync tracking, returns updated state record.

- getSyncState(mappingId, recordId): Queries sync_state table for mapping and record combination, retrieves last sync metadata (timestamps, version, checksums), checks if state exists (null if first sync), returns sync state object or null.

- aggregateSyncMetrics(timeRange): Queries sync_executions filtered by timeRange (last_hour, last_24h, last_7d, last_30d), calculates aggregate statistics (total executions, success count, failure count, total records processed, total errors, average duration), groups by mapping_id for per-mapping metrics, computes percentiles (p50, p95, p99) for duration, identifies top error types by frequency, calculates trend compared to previous period (percentage change), returns metrics object with time series data for charting.

- publishSyncEvent(eventType, payload): Validates eventType against allowed events (sync.started, sync.completed, sync.failed, sync.paused, sync.resumed, sync.cancelled, record.synced, conflict.detected, conflict.resolved, error.occurred), serializes payload to JSON, publishes to message queue (Redis Pub/Sub or RabbitMQ), broadcasts to connected WebSocket clients subscribed to event, logs event to event_log table, returns publish confirmation.

- subscribeToSyncEvents(clientId, eventTypes, callback): Validates eventTypes array contains valid event names, registers callback function for clientId, stores subscription in memory (Map of clientId to subscriptions), filters events by eventTypes before invoking callback, handles callback errors without breaking event loop, provides unsubscribe function in return, returns subscription object with unsubscribe method.

- initializeWorkerPool(workerCount): Spawns workerCount background worker processes, assigns worker IDs (1 to workerCount), establishes message passing channels between main and workers, distributes job queues evenly across workers, implements worker health checks every 30 seconds, handles worker crashes with automatic restart, maintains worker registry with status tracking, returns worker pool manager object.

- workerProcessJobs(workerId): Infinite loop that polls assigned job queue, retrieves next job with priority ordering (high, normal, low), locks job to prevent duplicate processing, deserializes job parameters, invokes appropriate sync function based on job type, handles job execution errors, updates job status (completed, failed), removes completed jobs from queue, sends heartbeat signal every 10 seconds, gracefully shuts down on SIGTERM, implements circuit breaker for repeated failures.

- scheduleSyncPolling(mappingId): Retrieves polling interval from mapping configuration, calculates next poll time (NOW() + interval), creates scheduled job in cron scheduler with unique identifier, stores schedule in sync_schedules table, validates no duplicate schedules exist, returns schedule ID and next execution timestamp.

- unscheduleSyncPolling(mappingId): Queries sync_schedules for mappingId, removes job from cron scheduler using schedule ID, deletes record from sync_schedules table, cancels any pending scheduled jobs in queue, logs unscheduling action, returns confirmation.

## DATA

- sync_executions: {id: UUID primary key, mapping_id: UUID foreign key to mappings, status: enum(pending|running|completed|failed|paused|cancelled), triggered_by: enum(scheduled|manual|api|cdc), user_id: UUID nullable for manual triggers, started_at: timestamp with timezone, completed_at: timestamp with timezone nullable, paused_at: timestamp nullable, cancelled_at: timestamp nullable, records_total: integer, records_processed: integer, records_succeeded: integer, records_failed: integer, errors_count: integer, conflicts_count: integer, duration_ms: integer computed, avg_records_per_sec: decimal computed, last_processed_id: string nullable for resume, cancellation_reason: text nullable, created_at: timestamp, updated_at: timestamp} - stores each sync execution instance with status tracking and performance metrics

- sync_logs: {id: bigint auto-increment primary key, execution_id: UUID foreign key to sync_executions with index, record_id: string indexed, field_name: string, old_value: jsonb nullable, new_value: jsonb nullable, log_type: enum(insert|update|delete|conflict|error|transformation|validation), is_compressed: boolean default false, error_message: text nullable, error_stack: text nullable, user_id: UUID nullable, timestamp: timestamp with timezone default NOW(), metadata: jsonb nullable} - detailed field-level audit trail for every data change during sync, partitioned by timestamp monthly

- sync_errors: {id: UUID primary key, execution_id: UUID foreign key to sync_executions with index, record_id: string indexed, error_type: enum(validation|transformation|network|api_limit|database|authentication|authorization|business_logic|unknown), error_code: string, error_message: text, error_stack: text, field_name: string nullable, source_value: jsonb nullable, retry_count: integer default 0, is_retriable: boolean, is_resolved: boolean default false, occurred_at: timestamp with timezone, resolved_at: timestamp nullable, resolution_notes: text nullable} - tracks all sync errors with categorization for analysis and alerting

- sync_state: {mapping_id: UUID, record_id: string, source_record_checksum: string, destination_record_checksum: string, last_synced_at: timestamp with timezone, sync_version: integer default 1, source_last_modified: timestamp with timezone, destination_last_modified: timestamp with timezone, sync_direction: enum(left_to_right|right_to_left|bidirectional), metadata: jsonb nullable, created_at: timestamp, updated_at: timestamp, PRIMARY KEY(mapping_id, record_id)} - maintains state for each record to detect conflicts and track sync history

- retry_queue: {id: UUID primary key, execution_id: UUID foreign key to sync_executions, record_id: string, job_type: enum(full_sync|record_sync|conflict_resolution), job_parameters: jsonb, retry_count: integer, max_retries: integer default 3, next_retry_at: timestamp with timezone indexed, priority: enum(high|normal|low), status: enum(pending|processing|completed|failed), error_message: text nullable, created_at: timestamp, updated_at: timestamp} - queue for failed sync operations with exponential backoff retry logic

- manual_resolution_queue: {id: UUID primary key, execution_id: UUID foreign key to sync_executions, record_id: string, mapping_id: UUID foreign key to mappings, conflict_details: jsonb, source_record: jsonb, destination_record: jsonb, last_synced_values: jsonb nullable, priority: integer default 5, status: enum(pending|in_review|resolved|escalated), assigned_to: UUID foreign key to users nullable, resolved_by: UUID foreign key to users nullable, resolved_at: timestamp nullable, resolution_action: enum(accept_source|accept_destination|custom_merge) nullable, resolution_values: jsonb nullable, created_at: timestamp, updated_at: timestamp} - queue for conflicts requiring manual human resolution with assignment tracking

- conflict_resolutions: {id: UUID primary key, execution_id: UUID foreign key to sync_executions, record_id: string, field_name: string, resolution_strategy: enum(source_wins|destination_wins|most_recent|field_priority|manual), source_value: jsonb, destination_value: jsonb, winning_value: jsonb, resolution_timestamp: timestamp with timezone, resolved_automatically: boolean, resolved_by: UUID nullable, resolution_metadata: jsonb, created_at: timestamp} - audit log of all conflict resolutions with strategy used and values selected

- sync_api_logs: {id: UUID primary key, execution_id: UUID foreign key to sync_executions with index, api_provider: enum(salesforce|destination), request_type: enum(query|insert|update|delete|upsert|cdc_subscribe), request_url: text, request_method: string, request_payload: jsonb nullable, response_status: integer, response_body: jsonb nullable, response_time_ms: integer, rate_limit_remaining: integer nullable, rate_limit_reset_at: timestamp nullable, error_message: text nullable, created_at: timestamp with timezone} - logs all API interactions for debugging and rate limit monitoring, partitioned by created_at monthly
