# TECHNICAL SPECIFICATION: SALESFORCE CONNECTOR

## OVERVIEW

Build a complete Salesforce integration system as the first external CRM connector for Renzo, establishing the architectural pattern for all future integrations. Implement secure OAuth 2.0 authentication, bidirectional field mapping configuration, intelligent conflict resolution, one-way data synchronization from Salesforce to Renzo's contact database, and comprehensive sync monitoring with detailed logging. This system stores encrypted OAuth tokens, maintains Salesforce record associations, and provides users full control over sync behavior through an intuitive UI integrated into the existing Settings page.

## VIEWS

- **IntegrationsSettingsSection**: New section within existing settings-view containing "Connected Systems" header, integration cards for each connector (initially only Salesforce), connection status indicators (green dot + "Connected" or gray dot + "Not Connected"), "Connect to Salesforce" button that launches OAuth flow, "Disconnect" button for active connections, and "Configure Sync" button to open field mapping modal.

- **SalesforceConnectModal**: OAuth connection modal (`.modal-overlay` with `.modal`) displaying Salesforce login instructions, "Authorize Renzo" primary button that opens Salesforce OAuth popup, loading spinner during token exchange, success confirmation with green checkmark and "Connection Successful!" message, error state showing red error icon with retry button, "Cancel" secondary button to abort connection flow.

- **SyncConfigurationModal**: Large modal for field mapping configuration with left column showing Salesforce fields (Account.Name, Account.AnnualRevenue, Account.LastActivityDate, Contact.Email, Contact.Phone, Contact.FirstName, Contact.LastName, Contract.EndDate), right column showing Renzo contact fields (name, email, phone, company, revenue, contractExpiry, lastContactDate), drag-and-drop or dropdown mapping interface, conflict resolution strategy selector per field (radio buttons: "Salesforce Wins", "Renzo Wins", "Manual Review"), "Save Mapping" and "Reset to Defaults" buttons, visual indicators for required mappings (email must be mapped).

- **SyncDashboardSection**: Dashboard area within integrations section showing last sync timestamp with relative time ("2 hours ago"), total contacts synced count with delta from previous sync (+15), success/error status badge, "Sync Now" primary action button with loading spinner during sync, progress bar during active sync operations, expandable error details section listing failed records with reasons, quick stats cards (New Contacts, Updated Contacts, Conflicts Detected, Last Sync Duration).

- **SyncLogModal**: Full-screen modal displaying paginated sync history table with columns (Timestamp, Operation Type, Records Affected, Status, Duration, User), expandable row details showing individual record changes (contact name, fields modified, old→new values), filter controls (date range picker, status filter, operation type filter), search functionality by contact name/email, "Export Log" button to download CSV, "Clear Old Logs" button with confirmation to remove logs older than 90 days.

- **ConflictResolutionModal**: Modal appearing when conflicts detected during sync with "Manual Review" strategy, displays each conflict as card showing contact name, conflicting field name, Renzo value vs Salesforce value with timestamps, side-by-side comparison view, radio buttons to choose which value to keep ("Keep Renzo Value", "Use Salesforce Value"), "Apply to All Similar" checkbox, batch action buttons ("Accept All Salesforce", "Keep All Renzo", "Review Individually"), progress indicator showing conflicts reviewed/total, "Apply Changes" button to commit selections.

- **IntegrationStatusBadge**: Reusable component showing connection health with color-coded dot (green=active, yellow=warning/needs reauth, red=error/disconnected, gray=not configured), tooltip on hover displaying detailed status (last successful sync, token expiry, error messages), pulsing animation during active sync operations.

## FUNCTIONS

- **initializeSalesforceIntegration()**: Check localStorage for existing Salesforce configuration on app load, decrypt stored OAuth tokens if present, validate token expiration dates, display connection status in UI, register sync event listeners, initialize sync interval timer if auto-sync enabled, restore last sync timestamp and stats from localStorage, set up OAuth callback listener for popup responses.

- **connectToSalesforce()**: Open SalesforceConnectModal, generate OAuth state parameter (random UUID) and store in sessionStorage for CSRF protection, construct Salesforce OAuth URL with client_id, redirect_uri (current origin + /oauth/callback), response_type=code, scope="api refresh_token", state parameter, open OAuth URL in popup window (600x700px centered), set up message listener for popup communication, handle popup blocked scenario with fallback instructions.

- **handleOAuthCallback(code, state)**: Receive authorization code and state from OAuth popup/redirect, validate state matches stored value from sessionStorage, exchange authorization code for access token and refresh token via Salesforce token endpoint (POST to https://login.salesforce.com/services/oauth2/token with grant_type=authorization_code, code, client_id, client_secret, redirect_uri), extract access_token, refresh_token, instance_url, issued_at from response, encrypt tokens using encryptToken() before storage, store encrypted tokens and instance_url in localStorage under key `salesforce_connection`, close OAuth popup, display success message in SalesforceConnectModal, automatically trigger initial sync with fetchSalesforceData(), update UI to show connected status.

- **encryptToken(token)**: Implement simple encryption for localStorage security, generate encryption key from user's email + static salt (stored in code), use Web Crypto API SubtleCrypto.encrypt() with AES-GCM algorithm, convert encrypted ArrayBuffer to base64 string for storage, return encrypted string (Note: for production, use server-side token storage, this provides basic obfuscation for local development).

- **decryptToken(encryptedToken)**: Reverse encryption process, convert base64 string back to ArrayBuffer, derive same encryption key from user email + salt, use SubtleCrypto.decrypt() with AES-GCM, convert decrypted ArrayBuffer to string token, return plaintext token, catch and handle decryption errors (corrupted data, wrong key).

- **refreshAccessToken()**: Detect expired access token (check issued_at timestamp + expires_in), retrieve encrypted refresh_token from localStorage, decrypt refresh token, POST to Salesforce token endpoint with grant_type=refresh_token, refresh_token, client_id, client_secret, receive new access_token and updated issued_at, encrypt and store new access token, update connection object in localStorage, return new access token for use in API calls, if refresh fails (invalid refresh token), trigger disconnectSalesforce() and show re-authentication modal.

- **disconnectSalesforce()**: Display confirmation dialog "Disconnect from Salesforce? Existing contacts will not be deleted.", on confirmation remove `salesforce_connection` from localStorage, remove `salesforce_field_mappings` from localStorage, remove `salesforce_sync_settings` from localStorage, update UI to show disconnected status, hide sync dashboard section, show "Connect to Salesforce" button again, optionally revoke OAuth token via Salesforce API (POST to revoke endpoint), log disconnection event to sync history.

- **fetchSalesforceData()**: Main sync orchestration function, validate Salesforce connection exists, check and refresh access token if needed, show sync progress UI (progress bar, "Syncing..." status), execute parallel API requests: fetchSalesforceAccounts() and fetchSalesforceContacts(), wait for both promises to resolve, pass results to mergeSalesforceData(), handle API errors (rate limits, network failures, invalid tokens), update sync dashboard with results (timestamp, counts, status), log sync operation to history, hide progress UI, show completion notification with summary stats.

- **fetchSalesforceAccounts()**: Retrieve access token and instance_url from localStorage, construct Salesforce SOQL query: "SELECT Id, Name, AnnualRevenue, LastActivityDate, Industry, Website, Phone FROM Account WHERE LastModifiedDate > [lastSyncTimestamp] ORDER BY LastModifiedDate DESC LIMIT 2000", send GET request to {instance_url}/services/data/v57.0/query?q={encodedQuery} with Authorization header "Bearer {access_token}", parse JSON response extracting records array, handle pagination if response.nextRecordsUrl exists (make additional requests), transform Salesforce Account objects to intermediate format {salesforceId, name, revenue, lastActivityDate, industry, website, phone, recordType: 'Account'}, return array of transformed account objects, catch and log API errors.

- **fetchSalesforceContacts()**: Construct SOQL query: "SELECT Id, Email, FirstName, LastName, Phone, AccountId, Title, Department, LeadSource FROM Contact WHERE LastModifiedDate > [lastSyncTimestamp] AND Email != null ORDER BY LastModifiedDate DESC LIMIT 2000", send GET request to Salesforce query endpoint with authorization, parse response records, handle pagination for large result sets, transform Contact objects to intermediate format {salesforceId, email, firstName, lastName, phone, accountId, title, department, leadSource, recordType: 'Contact'}, filter out records with null/invalid emails, return array of transformed contacts, track fetch duration for logging.

- **fetchContractData(accountIds)**: Secondary query to retrieve Contract information for accounts, construct SOQL: "SELECT Id, AccountId, EndDate, Status, ContractTerm FROM Contract WHERE AccountId IN ({accountIds}) AND Status = 'Activated'", send query request, parse results, create map of accountId → endDate for O(1) lookup, return contract map for merging with account data.

- **mergeSalesforceData(accounts, contacts)**: Apply user-configured field mappings from getSalesforceFieldMappings(), retrieve current Renzo contacts from localStorage, create email-based lookup map of existing contacts for O(1) matching, iterate through Salesforce contacts: for each contact check if email exists in Renzo database (match logic), if match found determine conflict resolution based on user settings and timestamps, if new contact create new record with mapped fields, join account data with contacts using accountId→Account.Id relationship, apply contract end dates from Contract data to contractExpiry field, collect conflicts requiring manual review into conflicts array, create arrays for newContacts, updatedContacts, conflictingContacts, apply automatic conflict resolution for "Salesforce Wins" and "Renzo Wins" strategies, if conflicts with "Manual Review" strategy exist show ConflictResolutionModal, update localStorage contacts array with merged results, track and return sync statistics {newCount, updatedCount, conflictCount, totalProcessed}.

- **getSalesforceFieldMappings()**: Retrieve custom field mappings from localStorage key `salesforce_field_mappings`, if not found return default mappings: {"Account.Name": "company", "Account.AnnualRevenue": "revenue", "Account.LastActivityDate": "lastContactDate", "Contact.Email": "email", "Contact.Phone": "phone", "Contact.FirstName+LastName": "name", "Contract.EndDate": "contractExpiry"}, validate mapping structure, ensure required fields (email) are mapped, return mapping object for use in data transformation.

- **saveSalesforceFieldMappings(mappings)**: Validate mappings object structure (check all required fields present), ensure email field is mapped (cannot be null), validate Salesforce field names against known schema, validate Renzo field names against contact model, store validated mappings to localStorage under `salesforce_field_mappings`, show success toast "Field mappings saved", update UI to reflect changes, trigger test mapping validation with sample data, log configuration change to sync history.

- **getSalesforceConflictSettings()**: Retrieve conflict resolution strategy from localStorage `salesforce_sync_settings`, return object with per-field strategies: {name: "salesforce_wins", email: "salesforce_wins", phone: "renzo_wins", company: "salesforce_wins", revenue: "salesforce_wins", contractExpiry: "salesforce_wins", lastContactDate: "salesforce_wins", notes: "manual_review", priority: "renzo_wins", relationship: "renzo_wins"}, if not configured return default (salesforce_wins for all CRM fields, renzo_wins for Renzo-specific fields), provide global default strategy setting.

- **saveSalesforceConflictSettings(settings)**: Validate settings object contains strategies for all contact fields, validate strategy values are one of: "salesforce_wins", "renzo_wins", "manual_review", store settings to localStorage `salesforce_sync_settings`, show confirmation message, update sync behavior immediately for next sync operation.

- **resolveFieldConflict(field, renzoValue, salesforceValue, renzoTimestamp, salesforceTimestamp, strategy)**: Core conflict resolution logic, if strategy is "salesforce_wins" return salesforceValue, if strategy is "renzo_wins" return renzoValue, if strategy is "manual_review" add to conflicts queue and return null (defer resolution), if strategy is "newest_wins" compare timestamps and return newer value, if values are identical return either value (no conflict), log resolution decision for audit trail.

- **showConflictResolutionModal(conflicts)**: Display ConflictResolutionModal with array of conflict objects {contactId, contactName, field, renzoValue, salesforceValue, renzoTimestamp, salesforceTimestamp}, render each conflict as card with side-by-side comparison, set up event listeners for resolution radio buttons, track user selections in resolvedConflicts map, enable "Apply Changes" button only when all conflicts resolved or "Apply to All" used, provide "Accept All Salesforce" shortcut that selects salesforceValue for all conflicts, provide "Keep All Renzo" shortcut for renzoValue, handle "Apply Changes" click by calling applyConflictResolutions().

- **applyConflictResolutions(resolutions)**: Receive map of contactId → {field → chosenValue}, retrieve contacts from localStorage, iterate through resolutions and update corresponding contact fields, validate chosen values before applying, save updated contacts back to localStorage, close ConflictResolutionModal, show success message "{count} conflicts resolved", update sync dashboard stats, log resolution actions to sync history with details of each decision.

- **performManualSync()**: Triggered by "Sync Now" button click, disable button and show loading spinner, validate Salesforce connection is active, check last sync timestamp to prevent duplicate syncs within 1 minute, call fetchSalesforceData() to execute sync, update lastSyncTimestamp in localStorage, display sync results in notification toast (e.g., "Sync complete: 45 contacts updated, 12 new, 3 conflicts"), re-enable sync button, increment sync counter in dashboard, handle errors gracefully with user-friendly messages ("Sync failed: Connection timeout. Retry?").

- **scheduleSyncOperation()**: Check if auto-sync is enabled in settings, if enabled set up setInterval() to call performManualSync() every N minutes (configurable, default 30 minutes), store interval ID for cleanup, respect user's active hours if configured (don't sync outside 9am-6pm), clear existing interval before creating new one, disable auto-sync if user manually disconnects Salesforce.

- **cancelScheduledSync()**: Clear sync interval using clearInterval(), update UI to remove "Next sync in X minutes" countdown, log cancellation event, called when user disables auto-sync or disconnects integration.

- **getSyncHistory()**: Retrieve sync logs from localStorage key `salesforce_sync_logs`, return array of log entries sorted by timestamp descending (newest first), each entry contains: {id, timestamp, operationType: 'manual'|'auto'|'initial', status: 'success'|'error'|'partial', recordsAffected, newCount, updatedCount, conflictCount, errorCount, duration, errors: [], userId}, limit to most recent 100 entries to prevent excessive storage, provide filtering helper methods.

- **addSyncLogEntry(entry)**: Validate log entry structure, generate unique ID for entry, add timestamp if not present, retrieve existing logs from localStorage, prepend new entry to array (newest first), trim array to 100 most recent entries, save updated logs back to localStorage `salesforce_sync_logs`, update sync dashboard to show latest entry, return entry ID for reference.

- **renderSyncLog()**: Display sync history in SyncLogModal, retrieve logs with getSyncHistory(), generate HTML table rows for each log entry, format timestamps as relative time ("2 hours ago") with tooltip showing absolute time, colorize status column (green for success, red for error, yellow for partial), show record counts as badges, implement expandable row details with arrow icon, on row click expand to show individual record changes, implement pagination controls (50 entries per page), add filter controls at top, set up search input with debounced filtering, attach event listeners to export and clear buttons.

- **exportSyncLog()**: Generate CSV file from sync logs, create header row with column names, iterate through filtered logs and format as CSV rows, handle special characters and commas in data (proper escaping), create Blob with CSV content, generate download link using URL.createObjectURL(), set filename as "renzo-salesforce-sync-log-{date}.csv", trigger download, revoke object URL after download, show success toast "Sync log exported".

- **clearOldSyncLogs()**: Show confirmation dialog "Delete sync logs older than 90 days? This cannot be undone.", on confirmation filter logs to keep only entries from last 90 days, calculate count of logs to be deleted, save filtered logs back to localStorage, show success message "{count} old logs deleted", refresh SyncLogModal display if open, log the cleanup operation itself.

- **validateSalesforceConnection()**: Periodic health check function, retrieve connection from localStorage, check if tokens exist, check token age against expiration, attempt simple API call (query single record) to verify connectivity, update connection status badge based on result, if validation fails show warning badge and "Reconnect" button, schedule automatic revalidation every 5 minutes, return boolean connection status.

- **renderIntegrationsSection()**: Build "Connected Systems" section HTML for settings view, create integration card for Salesforce with logo, connection status badge, description text "Sync contacts and accounts from Salesforce CRM", action buttons based on status (Connect/Disconnect/Configure), render sync dashboard if connected, render placeholder cards for future integrations (Gmail, HubSpot) with "Coming Soon" label, inject HTML into settings-view DOM at specific insertion point, attach event listeners to all buttons, apply existing Renzo styles and animations.

- **showSyncConfigurationModal()**: Display field mapping modal, load current mappings with getSalesforceFieldMappings(), load conflict settings with getSalesforceConflictSettings(), render two-column layout with Salesforce fields on left and Renzo fields on right, populate dropdowns with available fields, set selected values from current mappings, render conflict strategy radio buttons for each mapped field, highlight required mappings with asterisk, set up drag-and-drop functionality (optional enhancement), attach save button listener to call saveSalesforceFieldMappings(), attach reset button listener to restore defaults with confirmation, validate mappings on field change (ensure email is mapped).

- **testFieldMapping(mappings)**: Validation helper function, create sample Salesforce data objects (mock Account and Contact), apply provided mappings to transform sample data, validate all required Renzo fields are populated, check for data type compatibility (e.g., revenue should be numeric), return validation result with any errors or warnings, display results in configuration modal as inline feedback, use this before saving mappings to prevent broken sync configurations.

- **handleSyncError(error, context)**: Centralized error handler for sync operations, parse error object to determine type (network, authentication, rate limit, validation), log detailed error to console for debugging, create user-friendly error message based on type, show error notification to user with actionable suggestions (e.g., "Rate limit exceeded. Next sync available in 15 minutes."), add error to sync log with full details, if authentication error trigger token refresh or re-authentication flow, increment error counter in dashboard, provide retry button in notification for transient failures.

- **calculateSyncStatsDelta(currentStats, previousStats)**: Compare sync statistics between operations, calculate differences for each metric (newCount, updatedCount, conflictCount), format deltas with +/- prefix, determine trend direction (increasing, decreasing, stable), return delta object for display in dashboard, highlight significant changes (>10% change) in UI, store previous stats for next comparison.

- **formatSyncDuration(milliseconds)**: Convert sync duration to human-readable format, if < 1000ms show as "XXXms", if < 60000ms show as "X.Xs", if < 3600000ms show as "Xm Ys", otherwise show as "Xh Ym", use for displaying sync operation timing in logs and dashboard.

- **matchContactByEmail(email, existingContacts)**: Lookup helper function, normalize email to lowercase for comparison, iterate through existingContacts array to find match, return matched contact object or null, handle edge cases (empty email, malformed email), consider implementing fuzzy matching for common typos (optional enhancement).

- **isNewerData(salesforceTimestamp, renzoTimestamp)**: Timestamp comparison helper, parse ISO timestamp strings to Date objects, compare dates to determine which is newer, handle missing timestamps (treat as oldest), return boolean true if Salesforce data is newer, account for timezone differences (normalize to UTC), add buffer for clock skew (consider equal if within 5 seconds).

- **getSalesforceRecordId(contactId)**: Retrieve associated Salesforce record ID for Renzo contact, look up contact in database, extract salesforceId from contact metadata, return ID for future two-way sync operations, return null if contact not synced from Salesforce, use this to maintain bidirectional relationship between systems.

- **setSalesforceRecordId(contactId, salesforceId)**: Store Salesforce record association with Renzo contact, retrieve contact from database, add or update salesforceId field in contact metadata, add syncSource: 'salesforce' field, save updated contact, enable future sync operations to update correct records, preserve relationship when contact is updated in Renzo.

- **initializeOAuthCallbackListener()**: Set up message event listener for OAuth popup communication, listen for postMessage from OAuth callback page, validate message origin matches expected domain, extract code and state from message data, call handleOAuthCallback() with extracted parameters, handle timeout if no message received within 5 minutes, clean up listener after successful callback or timeout.

- **renderSyncProgress(progress)**: Update progress bar and status text during sync, calculate percentage complete (processed / total), update progress bar width with CSS, show current operation text ("Fetching accounts...", "Merging contacts...", "Resolving conflicts..."), animate progress smoothly with CSS transitions, show spinner during indeterminate operations, hide progress UI when sync complete.

- **showSyncNotification(stats)**: Display toast notification with sync results, format message based on stats: "{newCount} new, {updatedCount} updated", color-code notification (green for success, yellow for conflicts, red for errors), auto-dismiss after 5 seconds, provide "View Details" link to open sync log, stack multiple notifications if triggered rapidly, respect user's notification preferences if configured.

## DATA

- **salesforce_connection**: Object stored in localStorage containing {accessToken: string (encrypted), refreshToken: string (encrypted), instanceUrl: string, issuedAt: number (timestamp), expiresIn: number (seconds), connectedAt: number (timestamp), userId: string (Salesforce user ID), orgId: string (Salesforce org ID), status: 'active'|'expired'|'error'}.

- **salesforce_field_mappings**: Object mapping Salesforce field paths to Renzo contact field names, format: {[salesforceField: string]: renzoField: string}, example: {"Account.Name": "company", "Contact.Email": "email", "Contact.FirstName+LastName": "name"}, includes special handling for compound fields (FirstName+LastName), stored in localStorage as JSON string.

- **salesforce_sync_settings**: Object containing sync configuration, format: {conflictResolution: {[field: string]: 'salesforce_wins'|'renzo_wins'|'manual_review'}, autoSyncEnabled: boolean, syncIntervalMinutes: number, lastSyncTimestamp: number, syncOnConnect: boolean, respectActiveHours: boolean, activeHoursStart: number (hour 0-23), activeHoursEnd: number (hour 0-23)}.

- **salesforce_sync_logs**: Array of sync operation logs, each entry: {id: string (UUID), timestamp: number, operationType: 'manual'|'auto'|'initial', status: 'success'|'error'|'partial', recordsAffected: number, newCount: number, updatedCount: number, conflictCount: number, errorCount: number, duration: number (milliseconds), errors: Array<{contactEmail: string, error: string}>, userId: string, triggerSource: string}, stored in localStorage, limited to 100 most recent entries.

- **salesforce_last_sync**: Simple object storing {timestamp: number, status: string, recordCount: number} for quick dashboard display without parsing full logs, updated after each sync operation.

- **contact.salesforceId**: New field added to existing contact objects, stores Salesforce record ID (either Account.Id or Contact.Id depending on source), format: string (18-character Salesforce ID), used for future two-way sync to update correct records, remains null for contacts not synced from Salesforce.

- **contact.syncSource**: New field indicating origin of contact, values: 'manual'|'salesforce'|'import', helps determine conflict resolution priority, stored as string on each contact object, defaults to 'manual'
