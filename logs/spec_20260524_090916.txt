# TECHNICAL SPECIFICATION: Full Mobile Responsive Layout Rework

## OVERVIEW
Transform the desktop-only layout into a fully responsive mobile experience. On screens ≤768px, convert the vertical sidebar into a bottom tab bar with emoji icons, add a fixed top header, switch the contacts table to card view, and optimize all interactive elements for touch. This is a CSS-heavy layout rework with one JavaScript function modification for responsive table rendering.

## VIEWS
- **mobileHeader**: Fixed top bar (mobile only) showing Renzo logo left, user name center, logout icon right. Height 52px, background var(--sidebar), z-index 500.
- **bottomNavBar**: Transformed sidebar at bottom, 56px height, horizontal flex layout with 8 nav items, each showing emoji icon above label.
- **contactCards**: Replace table rows with card layout on mobile, each card displaying contact info with badges and action button.
- **responsiveModals**: Bottom-sheet style modals on mobile, sliding up from bottom with rounded top corners.

## FUNCTIONS
- **renderContacts()**: Modify existing function to detect viewport width. If window.innerWidth <= 768, render card layout instead of table rows. Card structure: wrapper div .contact-card containing .card-header (name + priority badge), .card-body (company, tier badge, status badge row), .card-footer (Message button). Otherwise render existing table layout. Use contactsData array, loop through each contact, build card HTML string, insert into container. Cards get click handler for opening contact detail modal.

- **initMobileLayout()**: Call on DOMContentLoaded and window resize (debounced 250ms). Check if window.innerWidth <= 768, add class 'mobile-layout' to body, show mobileHeader, hide sidebar-logo and sidebar-footer. If > 768, remove 'mobile-layout', hide mobileHeader, show sidebar-logo and sidebar-footer. Update renderContacts call to refresh view.

- **handleMobileResize()**: Debounce wrapper for initMobileLayout. Store timeout ID, clear previous timeout on each call, set new timeout 250ms to call initMobileLayout. Prevents excessive layout recalculations during resize.

## DATA
- **isMobileView**: Boolean flag, true if window.innerWidth <= 768, updated on resize, used by render functions to determine layout mode.
- **navItems**: Array of objects with emoji, label, view name for bottom nav: [{emoji: '🏠', label: 'Dashboard', view: 'dashboard'}, {emoji: '👥', label: 'Contacts', view: 'contacts'}, {emoji: '📤', label: 'Queue', view: 'queue'}, {emoji: '📝', label: 'Drafts', view: 'drafts'}, {emoji: '⚡', label: 'Batch', view: 'batch'}, {emoji: '🔗', label: 'Integrations', view: 'integrations'}, {emoji: '📊', label: 'Activity', view: 'activity'}, {emoji: '⚙', label: 'Settings', view: 'settings'}].
- **mobileHeaderHTML**: String template for top header structure, inserted into DOM on init.

## API
No external API changes. This is a pure frontend layout modification.

## ERRORS
- **Viewport width detection failure**: If window.innerWidth returns undefined, default to desktop layout and log warning.
- **Missing DOM elements**: If mobileHeader insert fails (container not found), log error but continue with bottom nav transformation.
- **Resize thrashing**: Debounce ensures max one layout recalc per 250ms. If browser freezes, increase debounce to 500ms.
- **Touch event conflicts**: Use passive event listeners for scroll performance. If cards don't respond to tap, check z-index stacking.
- **Badge overflow**: If nav badges overlap on small screens, reduce badge font size to 9px and padding to 2px 4px.
- **Modal height overflow**: Max-height 90vh with overflow-y auto on modal-body. If content still truncated, add padding-bottom 20px to modal-body.
- **Table/card sync issue**: If contacts render as both table and cards, ensure display:none is applied correctly in media query and JS checks width before rendering.
