# TECHNICAL SPECIFICATION: Field Mapping Configuration UI

## OVERVIEW

Build a comprehensive field mapping management system enabling non-technical users to configure bidirectional field synchronization between Salesforce and Renzo. The system provides visual mapping creation, transformation logic configuration, real-time validation, and testing capabilities. The interface leverages existing modal/table patterns while introducing specialized components for schema browsing, transformation building, and mapping validation with inline error resolution.

## VIEWS

- **MappingListView** (`/sync/mappings`): Primary management interface displaying all field mappings in a filterable data table. Shows source field, destination field, sync direction badge, transformation type, active status toggle, and last modified timestamp. Includes search bar filtering by field names, direction filter dropdown, status filter toggle, bulk action checkboxes, and prominent "Create New Mapping" button in page header. Empty state displays onboarding message with "Create First Mapping" CTA. Uses existing `.card`, `.table-container` patterns with custom `.mapping-row` styling for data type icons and transformation indicators.

- **MappingEditorModal**: Full-screen modal (900px width) with three-column layout for creating/editing mappings. Left column contains source field selector with collapsible object tree and searchable dropdown showing Salesforce objects and fields with data type icons. Center column shows direction selector (three radio buttons with arrow icons) and transformation configuration panel that dynamically changes based on selected transformation type. Right column displays destination field selector with Renzo schema tree and compatibility indicator showing green checkmark or red warning for data type mismatches. Bottom section contains conflict resolution dropdown, active/inactive toggle, validation error panel, and action buttons (Test Mapping, Cancel, Save Mapping).

- **TransformationBuilder**: Tabbed interface within MappingEditorModal that switches configuration panels based on transformation type. Date Format tab shows source format dropdown, destination format input with live preview using sample date. Text Transform tab displays operation dropdown (uppercase/lowercase/trim/regex), regex pattern input with test string field. Picklist Mapping tab renders editable table with source value and destination value columns, add/remove row buttons. Formula Builder tab provides token dropdown for field insertion, operator buttons (+, -, *, /, concatenate), function library dropdown (IF, CASE, ROUND, SUBSTRING), and formula preview pane showing parsed expression. Custom Function tab embeds CodeMirror editor with JavaScript syntax highlighting, parameter schema JSON editor, and syntax error display panel.

- **SchemaExplorer**: Collapsible tree component used in both source and destination field selectors. Root level shows Salesforce objects (Account, Contact, Opportunity, Custom Objects) or Renzo entities (Property, Unit, Lease, Tenant). Clicking object expands to show fields with icons indicating data type (text, number, date, boolean, picklist, reference). Each field row displays field API name, label, data type badge, and "Select" button. Includes search input at top filtering tree nodes in real-time. Selected field highlights in blue with checkmark icon.

- **ValidationPanel**: Collapsible accordion section within MappingEditorModal showing real-time validation results. Each validation check displays as expandable row with severity icon (error red X, warning yellow triangle, success green check). Error rows show descriptive message and "Learn More" link expanding inline help text with resolution steps. Checks include: field existence verification, data type compatibility assessment, transformation syntax validation, circular dependency detection, required field mapping confirmation. Panel header shows aggregate validation score (5/5 checks passed) with colored indicator bar.

- **TestMappingPanel**: Slide-out drawer (400px width) triggered by "Test Mapping" button. Top section provides sample data input form with fields dynamically generated based on source schema. Users enter test values, click "Run Test" button. Results section displays three columns: original source value, transformation process (step-by-step breakdown if formula/custom function), final destination value. Shows data type conversions, applied transformations, and final output. Error messages display in red if transformation fails. "Copy Configuration" button exports test scenario as JSON for debugging.

- **ImportExportModal**: Simple modal with two tabs. Export tab displays JSON code block of all mappings with "Copy to Clipboard" and "Download JSON" buttons. Shows export timestamp and mapping count. Import tab provides file upload dropzone accepting .json files, validates schema on selection, displays preview table of mappings to import with checkboxes for selective import. "Import Selected" button applies mappings, handling conflicts with overwrite confirmation dialog. Progress indicator shows import status for batch operations.

- **BulkActionsBar**: Sticky bar appearing at bottom of MappingListView when checkboxes selected. Shows selection count, "Select All" checkbox, action buttons (Activate, Deactivate, Delete with trash icon). Delete button triggers confirmation modal listing selected mappings. Bar slides up from bottom with animation, includes "Clear Selection" X button on right edge.

## FUNCTIONS

- **initMappingListView()**: Initializes main mapping list page on route `/sync/mappings`. Calls `fetchMappings()` to load data, renders table using `renderMappingTable(mappings)`, attaches event listeners to search input with 300ms debounce calling `filterMappings(query)`, attaches listeners to direction filter dropdown calling `applyFilters()`, attaches listener to status toggle calling `applyFilters()`, attaches listener to "Create New Mapping" button calling `openMappingEditor(null)`. Sets up interval polling `fetchMappings()` every 30 seconds for real-time updates. Initializes bulk action checkboxes with `setupBulkActions()`.

- **fetchMappings(filters)**: Async function making GET request to `/api/mappings` with optional filter parameters (direction, status, search query). Returns array of mapping objects with structure: {id, source_system, source_field, source_label, destination_system, destination_field, destination_label, direction, transformation_type, transformation_config, conflict_resolution, is_active, created_at, updated_at, last_sync}. Handles loading states by showing skeleton rows, catches errors displaying toast notification with retry button. Caches results in `mappingsCache` object keyed by filter hash for 60-second TTL.

- **renderMappingTable(mappings)**: Renders data table by clearing `.table tbody`, iterating mappings array, creating row element for each with cells: checkbox (if bulk actions enabled), source field with data type icon, destination field with data type icon, direction badge using `renderDirectionBadge(direction)`, transformation type label with icon, status toggle switch calling `toggleMappingStatus(id, currentStatus)`, timestamp formatted with `formatRelativeTime(updated_at)`, actions dropdown with Edit/Delete/Duplicate options. Attaches click listener to row (except checkbox/toggle/actions) calling `openMappingEditor(mapping.id)`. Applies zebra striping with `:nth-child(even)` CSS. If mappings empty, renders empty state with illustration and "Create First Mapping" button.

- **openMappingEditor(mappingId)**: Opens mapping editor modal for create (null mappingId) or edit (existing mappingId). If editing, calls `fetchMapping(mappingId)` to load full configuration. Creates modal overlay div, appends modal structure with header showing "Create Field Mapping" or "Edit Field Mapping", renders three-column layout with `renderSourceFieldSelector()`, `renderDirectionSelector()`, `renderDestinationFieldSelector()`. If editing, pre-populates form fields from loaded data. Renders `renderTransformationBuilder()` with selected type. Renders `renderValidationPanel()` calling `validateMapping()`. Attaches listener to Test button calling `openTestPanel()`, Cancel button calling `closeModal()`, Save button calling `saveMappingConfiguration()`. Initializes real-time validation on field changes.

- **renderSourceFieldSelector(selectedField)**: Renders left column source field selector. Creates search input with placeholder "Search Salesforce fields". Calls `fetchSalesforceSchema()` async function getting field metadata. Renders collapsible tree with `renderSchemaTree(schema, 'salesforce')`. Each object node (Account, Contact, etc.) shows expand/collapse chevron, clicking toggles child field visibility. Field nodes show API name, label in gray, data type icon (text='T', number='#', date='📅', boolean='☑', picklist='▼', reference='🔗'), and radio button. Clicking field radio calls `selectSourceField(field)` which highlights row, updates `selectedSourceField` state, triggers `validateDataTypeCompatibility()`, updates transformation builder visibility. If selectedField passed, pre-selects and expands to that field.

- **renderDestinationFieldSelector(selectedField)**: Renders right column destination field selector identical to source but for Renzo schema. Calls `fetchRenzoSchema()` getting Renzo entities (Property, Unit, Lease, Tenant, etc.) and their fields. Renders with `renderSchemaTree(schema, 'renzo')`. Selection calls `selectDestinationField(field)` which updates state, triggers `validateDataTypeCompatibility()` showing inline compatibility indicator. If data types incompatible (e.g., Text to Number), displays yellow warning icon with tooltip: "Data type mismatch - transformation required". If compatible, shows green checkmark. Updates transformation dropdown to show recommended transformations for the data type pair.

- **renderDirectionSelector(currentDirection)**: Renders center column direction selector with three radio button options arranged vertically: "Salesforce → Renzo" (to-renzo), "Renzo → Salesforce" (to-salesforce), "Bidirectional ⇄" (bidirectional). Each option styled as large card (200px x 80px) with icon, label, and description text. Clicking radio calls `selectDirection(direction)` which updates `selectedDirection` state, triggers `validateCircularDependencies()` if bidirectional, updates conflict resolution visibility (only shown for bidirectional). Pre-selects currentDirection if provided.

- **renderTransformationBuilder(transformationType, config)**: Renders transformation configuration panel that switches UI based on transformationType parameter (none, date_format, text_transform, picklist_mapping, formula, custom_function). Creates tabbed interface with tab for each type. "None" shows message "No transformation applied - values synced as-is". "Date Format" renders two dropdowns (source format with options: MM/DD/YYYY, DD/MM/YYYY, YYYY-MM-DD, ISO 8601, Unix Timestamp; destination format with same options), live preview div showing sample date conversion. "Text Transform" renders operation dropdown (uppercase, lowercase, trim, regex_replace), conditional regex pattern input and replacement input shown only for regex option, test input and result output. "Picklist Mapping" renders editable table using `renderPicklistMappingTable(config.mappings)`. "Formula" renders `renderFormulaBuilder(config.formula)`. "Custom Function" renders CodeMirror editor using `renderCustomFunctionEditor(config.code)`. Attaches change listeners to all inputs calling `updateTransformationConfig()` which updates config object and triggers validation.

- **renderPicklistMappingTable(mappings)**: Renders table with columns "Salesforce Value" and "Renzo Value". Each row has two text inputs and delete button. Iterates mappings array (array of {source, destination} objects) creating row for each. "Add Row" button at bottom calls `addPicklistMappingRow()` which inserts new row with empty inputs. Delete button calls `removePicklistMappingRow(index)` which splices from array and re-renders. Validates on change that no duplicate source values exist, shows error if duplicates found. Auto-fetches picklist values from Salesforce schema using `fetchPicklistValues(fieldName)` and renders dropdown suggestions for source column. Destination column shows Renzo picklist values if destination is picklist type.

- **renderFormulaBuilder(formula)**: Renders formula construction interface with three sections. Top section shows token dropdown populated with available fields from source object (calling `getAvailableFields(sourceObject)`), clicking token inserts at cursor position in formula textarea with `{FieldName}` syntax. Middle section shows operator button grid (+, -, *, /, ==, !=, <, >, AND, OR, concatenate) each calling `insertOperator(op)` at cursor. Function library dropdown with categories (Math: ROUND, ABS, CEILING, FLOOR; Text: SUBSTRING, CONCAT, TRIM, UPPER, LOWER; Logical: IF, CASE, AND, OR; Date: NOW, DATEADD, DATEDIFF). Clicking function inserts template with placeholder params: `IF(condition, true_value, false_value)`. Bottom section shows formula textarea with syntax highlighting detecting `{tokens}` in blue, operators in purple, functions in green. Below textarea, preview pane calls `parseFormula(formula)` showing parsed abstract syntax tree or syntax errors in red.

- **renderCustomFunctionEditor(code)**: Initializes CodeMirror editor with JavaScript mode, theme 'material-darker', line numbers enabled, auto-closing brackets. Pre-populates with code parameter or default template: `function transform(sourceValue, context) { \n  // context.sourceField, context.destinationField available\n  return sourceValue;\n}`. Below editor, renders parameter schema JSON editor (also CodeMirror with mode 'application/json') for defining expected parameters. Syntax validation runs on change using `validateJavaScript(code)` which uses esprima parser, displays errors below editor with line number links jumping to error location. "Test Function" button opens inline test panel with parameter inputs and output display calling `testCustomFunction(code, params)` executing in sandboxed context.

- **validateMapping()**: Comprehensive validation function returning validation results object with checks array. Each check has {id, severity ('error'|'warning'|'success'), message, helpText}. Runs sequentially: (1) `validateFieldExistence()` checking source and destination fields exist in schemas, (2) `validateDataTypeCompatibility()` checking if data types compatible or transformation configured, (3) `validateTransformationSyntax()` checking formula syntax or custom function validity, (4) `validateCircularDependencies()` checking if bidirectional mapping creates circular reference by calling `detectCircularDeps(sourceField, destinationField)` which queries existing mappings and builds dependency graph using depth-first search, (5) `validateRequiredFields()` checking if all required fields populated. Returns aggregate {isValid: boolean, errors: [], warnings: [], checks: []}. Called on every field change with 500ms debounce.

- **renderValidationPanel(validationResults)**: Renders validation accordion displaying results from `validateMapping()`. Header shows "Validation Results (3 errors, 1 warning)" with color-coded icon (red if errors, yellow if warnings, green if all passed). Body contains accordion items for each check, grouped by severity. Error items expanded by default, warning/success collapsed. Each item shows icon, check name, message. Expandable items show detailed helpText with resolution steps and "Learn More" links to documentation. If all checks pass, shows success message "All validation checks passed ✓" with green background. Re-renders on validation state change.

- **saveMappingConfiguration()**: Async function saving mapping configuration. Validates using `validateMapping()`, if errors exist shows toast "Please fix validation errors before saving" and highlights first error in UI. If valid, constructs mapping payload object: {source_system: 'salesforce', source_field: selectedSourceField, destination_system: 'renzo', destination_field: selectedDestinationField, direction: selectedDirection, transformation_type: selectedTransformationType, transformation_config: transformationConfig object, conflict_resolution: selectedConflictResolution, is_active: isActive}. If editing (mappingId exists), makes PUT request to `/api/mappings/${mappingId}` with payload. If creating, makes POST request to `/api/mappings`. Shows loading spinner on Save button during request. On success, shows toast "Mapping saved successfully", closes modal, calls `fetchMappings()` to refresh list. On error, shows toast with error message, keeps modal open highlighting field-specific errors if returned by API.

- **openTestPanel(mappingConfig)**: Opens slide-out test panel from right side. Renders sample data input form dynamically based on source field data type. Text fields render text input, date fields render date picker, boolean renders checkbox, picklist renders dropdown with values, number renders number input. "Run Test" button calls `testMapping(mappingConfig, sampleData)` which makes POST request to `/api/mappings/test` with payload {source_field, destination_field, transformation_type, transformation_config, sample_value}. Response contains {original_value, steps: [{description, input, output}], final_value, success, error}. Renders three-column result display: left shows original value with data type, center shows transformation steps as vertical stepper with arrow between steps, right shows final value with data type. If error, displays error message in red box with stack trace in expandable details section. "Copy Configuration" button copies full config JSON to clipboard for debugging support.

- **testMapping(config, sampleData)**: Async function testing mapping transformation. Makes POST request to `/api/mappings/test` endpoint with {source_field: config.source_field, destination_field: config.destination_field, transformation_config: config.transformation_config, sample_data: sampleData}. Server-side executes transformation in isolated context and returns {success: boolean, result: {original, steps: [], final}, error: string}. Returns promise resolving to result object. Handles timeout after 5 seconds showing error "Transformation test timed out". Catches network errors showing generic error message.

- **toggleMappingStatus(mappingId, currentStatus)**: Async function toggling mapping active status. Makes PATCH request to `/api/mappings/${mappingId}` with payload {is_active: !currentStatus}. Optimistically updates UI by toggling switch immediately, shows loading spinner on switch. If request fails, reverts switch state and shows error toast "Failed to update mapping status". On success, shows brief success toast "Mapping activated" or "Mapping deactivated". Updates mappings cache to reflect change.

- **deleteMapping(mappingId)**: Async function deleting mapping with confirmation. Shows confirmation modal "Are you sure you want to delete this mapping? This action cannot be undone." with Cancel and Delete buttons. If confirmed, makes DELETE request to `/api/mappings/${mappingId}`. Shows loading state, on success removes row from table with fade-out animation, shows toast "Mapping deleted successfully", calls `fetchMappings()` to refresh. On error, shows toast with error message. If mapping currently active, shows additional warning in confirmation modal "This mapping is currently active and will stop syncing data."

- **setupBulkActions()**: Initializes bulk action functionality. Attaches change listener to master checkbox in table header calling `toggleAllSelections()` which checks/unchecks all row checkboxes. Attaches change listener to row checkboxes calling `updateBulkActionBar()` which counts selected rows, shows/hides bulk action bar with slide-up animation, updates count display "3 mappings selected". Attaches click listeners to bulk action buttons: Activate calls `bulkActivateMappings(selectedIds)`, Deactivate calls `bulkDeactivateMappings(selectedIds)`, Delete calls `bulkDeleteMappings(selectedIds)` with confirmation modal showing list of selected mappings. Clear Selection button calls `clearAllSelections()` hiding bar.

- **bulkActivateMappings(mappingIds)**: Async function activating multiple mappings. Shows progress modal with progress bar "Activating mappings... 2/5". Iterates mappingIds array making PATCH request for each to `/api/mappings/${id}` with {is_active: true}. Updates progress bar after each request. If any fail, collects errors and shows summary modal "3 mappings activated successfully, 2 failed" with expandable error details. On completion, closes progress modal, shows success toast, calls `fetchMappings()` to refresh, clears selections hiding bulk action bar.

- **bulkDeactivateMappings(mappingIds)**: Identical to `bulkActivateMappings` but sets is_active: false. Shows "Deactivating mappings..." progress. Same error handling and completion flow.

- **bulkDeleteMappings(mappingIds)**: Async function deleting multiple mappings with confirmation. Shows confirmation modal "Are you sure you want to delete 3 mappings? This action cannot be undone." with list of mapping names. If confirmed, shows progress modal "Deleting mappings... 1/3". Iterates mappingIds making DELETE requests. Collects errors, shows summary on completion. Refreshes table, clears selections, shows toast with result summary.

- **openImportExportModal()**: Opens import/export modal with two tabs. Export tab pre-selected by default. Calls `generateExportJSON()` which fetches all mappings using `fetchMappings()` with no filters, formats as JSON with structure {version: '1.0', exported_at: timestamp, mappings: []}. Renders JSON in read-only CodeMirror editor with copy button calling `copyToClipboard(json)` and download button calling `downloadJSON(json, 'renzo-mappings-export.json')`. Import tab renders file upload dropzone accepting `.json` files. On file selection, reads file using FileReader, validates structure with `validateImportJSON(json)` checking version compatibility and schema validity. If valid, parses mappings and renders preview table with checkboxes for selective import. "Import Selected" button calls `importMappings(selectedMappings)`.

- **importMappings(mappings)**: Async function importing mapping configurations. Shows progress modal "Importing mappings... 0/5". Iterates mappings array, for each checks if mapping with same source_field+destination_field exists using `checkMappingExists(source, destination)`. If exists, shows conflict modal "Mapping already exists. Overwrite or skip?" with Overwrite/Skip/Skip All buttons. If overwrite, makes PUT request to existing mapping ID. If not exists, makes POST request creating new. Updates progress bar after each. On completion, shows summary modal "5 mappings imported successfully, 2 skipped, 1 failed" with details. Calls `fetchMappings()` to refresh table.

- **filterMappings(query)**: Client-side filtering function for search input. Filters cached mappings array by checking if query matches source_field, source_label, destination_field, or destination_label (case-insensitive). Re-renders table with filtered results using `renderMappingTable(filteredMappings)`. If no results, shows "No mappings found matching '{query}'" message with "Clear Search" button.

- **applyFilters()**: Applies multiple filter criteria simultaneously. Reads values from direction filter dropdown and status toggle. Constructs filter object {direction: selectedDirection || 'all', status: statusToggle ? 'active' : 'all', search: searchQuery}. Calls `fetchMappings(filters)` if server-side filtering preferred, or filters cached results if client-side. Updates URL query params with `updateURLParams(filters)` for shareable filtered views. Re-renders table with filtered results.

- **fetchSalesforceSchema()**: Async function retrieving Salesforce field metadata. Makes GET request to `/api/fields/salesforce` returning array of objects with structure [{object_name, object_label, fields: [{api_name, label, data_type, is_required, picklist_values, reference_to}]}]. Caches result in sessionStorage with key 'salesforce_schema' and 2-hour TTL. Returns promise resolving to schema object. On error, shows toast "Failed to load Salesforce schema" with retry button. Handles loading state with skeleton tree structure.

- **fetchRenzoSchema()**: Async function retrieving Renzo database schema. Makes GET request to `/api/fields/renzo` returning similar structure to Salesforce schema but for Renzo entities (Property, Unit, Lease, Tenant, etc.). Caches in sessionStorage with key 'renzo_schema'. Returns promise resolving to schema. Same error handling as `fetchSalesforceSchema`.

- **renderSchemaTree(schema, system)**: Recursive function rendering collapsible tree structure. Creates root ul element, iterates objects in schema creating li for each with object name, expand/collapse chevron icon, and nested ul for fields. Field items show icon based on data_type, field label with API name in gray text, and select radio button. Attaches click listener to object row calling `toggleObjectExpansion(objectName)` which adds/removes `.expanded` class showing/hiding children with slide-down animation. Attaches click listener to field radio calling appropriate select function (`selectSourceField` or `selectDestinationField` based on system param). Implements search highlighting by adding `.highlight` class to nodes matching search query. Returns tree DOM element for appending to container.

- **selectSourceField(field)**: Updates `selectedSourceField` state with field object containing {object_name, api_name, label, data_type, is_required}. Highlights selected field row adding `.selected` class and checkmark icon. Calls `validateDataTypeCompatibility()` if destination field already selected. Updates transformation type dropdown showing recommended transformations based on data type (e.g., if date field, shows Date Format option prominently). If formula builder open, updates available fields list for token insertion. Triggers validation with `validateMapping()`.
