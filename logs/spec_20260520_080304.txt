# TECHNICAL SPECIFICATION: SYNC MAPPING CONFIGURATION INTERFACE

## OVERVIEW

A comprehensive sync mapping configuration system built with vanilla JavaScript, HTML, and CSS. The application manages bidirectional data synchronization between Salesforce and target systems through an intuitive wizard-based interface. The system includes a mapping list page with search/filter capabilities, a seven-step creation wizard with drag-and-drop field mapping, real-time validation, conflict resolution strategies, and version history tracking. All data persists to localStorage with simulated REST API endpoints, providing full CRUD operations, inline validation, and detailed error handling.

## VIEWS

- **MappingListView**: Primary table view displaying all sync mappings with columns for name, source/target objects, sync direction, status badges, last sync timestamp, and success rate percentage. Includes search bar with debounced filtering, dropdown filters for status and direction, action buttons (Create New, Refresh), and inline row actions (Edit icon, Pause/Resume toggle, Duplicate icon, Delete icon with confirmation). Empty state shows illustration and CTA when no mappings exist.

- **MappingWizardView**: Multi-step modal wizard (1200px width) with progress indicator showing 8 steps (Basic Info, Objects, Field Mapping, Transformations, Validation, Conflicts, Schedule, Review). Left sidebar displays step numbers with checkmarks for completed steps, active step highlighted in primary color. Main content area shows current step form with Previous/Next/Save buttons in footer. Each step has validation that blocks progression until requirements met.

- **Step1BasicInfoForm**: Form with mapping name input (required, max 100 chars), description textarea (optional, max 500 chars), sync direction dropdown with three options (Salesforce → Target, Target → Salesforce, Bidirectional) represented by arrow icons. Real-time character counters below inputs. Inline validation shows error messages below fields.

- **Step2ObjectSelectionForm**: Two-column layout - left for source (Salesforce), right for target. Each column has system selector dropdown (Salesforce predefined, target systems loaded from config) and object dropdown with searchable select. Object dropdowns populated via async simulation of metadata API calls. Loading spinners show during fetch. Object selection triggers field metadata load for next step.

- **Step3FieldMappingBuilder**: Split-pane interface with source fields list (left, 40% width), mapping canvas (center, 20% width), target fields list (right, 40% width). Each field displayed as draggable card with field name, type icon (text, number, date, boolean), and required indicator (red asterisk). Canvas shows SVG connection lines between mapped fields. Unmapped required fields highlighted with yellow background. Auto-map button at top attempts name-based matching with fuzzy logic. Manual mapping via drag-from-source-drop-on-target or click-source-click-target modes. Delete mapping via X icon on connection line.

- **Step4TransformationRulesForm**: Table view of mapped fields with transformation type dropdown per row (Direct Copy default, Formula, Lookup, Custom Function). When non-direct selected, inline expression editor appears with Monaco-style syntax highlighting (simulated with textarea and pattern matching). Test button per row opens modal with sample input field, executes transformation logic, shows output or error. Formula syntax supports field references ${fieldName}, operators (+, -, *, /), functions (UPPER, LOWER, CONCAT, DATE_FORMAT). Lookup requires lookup object and match field selectors.

- **Step5ValidationRulesForm**: Dynamic rule builder with Add Rule button creating new rule row. Each row contains field selector dropdown (mapped fields only), operator dropdown (equals, not equals, contains, starts with, ends with, regex, greater than, less than, is empty, is not empty), value input (text/number based on operator), error message textarea (shown when validation fails), and Delete Rule icon. Rules evaluated in order with AND logic. OR grouping via parenthetical rule groups (advanced mode toggle).

- **Step6ConflictResolutionForm**: Radio button group with five strategies: Source Wins (always use source value), Target Wins (always use target value), Most Recent Wins (timestamp-based comparison), Manual Review Required (flag for human review), Custom Logic (JavaScript expression editor). Description paragraph below each radio explains behavior. Custom Logic option shows code editor with context variables (sourceValue, targetValue, sourceTimestamp, targetTimestamp, fieldName) and must return winning value.

- **Step7SyncScheduleForm**: Radio group for sync mode (Real-time with polling interval number input in minutes, Scheduled with cron expression input and helper text, Manual only). Polling interval validates 1-1440 minute range. Cron expression validates against standard cron format with visual builder button opening cron editor modal (day/time selectors). Sync filter section with WHERE clause builder - Add Condition button creates condition rows (field dropdown, operator, value input) with AND/OR toggles. Raw SQL preview shown below builder with syntax highlighting.

- **Step8ReviewSummary**: Read-only summary cards displaying all configured settings in organized sections (Basic Info, Objects, Field Mappings count with expandable list, Transformations count, Validation Rules count, Conflict Strategy, Schedule details). Test Mapping button at top runs validation simulation against sample data loaded from metadata, shows progress modal with validation steps (Field mapping validation, Transformation execution, Validation rules check, Conflict resolution test), displays results with success/warning/error counts and detailed messages list. Footer buttons: Save as Draft (inactive), Save & Activate (active), Cancel.

- **MappingEditView**: Identical to MappingWizardView but pre-populated with existing mapping data loaded from localStorage. Additional version history sidebar (300px width, collapsible) on right showing chronological list of changes (timestamp, user, change summary, Restore button). Restore opens confirmation modal, reverts mapping to selected version. Save creates new version entry. Exit without saving shows unsaved changes confirmation modal.

- **ConfirmationModal**: Reusable modal (400px width) with warning icon, title prop, message prop, Cancel button (secondary), Confirm button (danger for deletes, primary otherwise). Blocks background interaction with overlay. Escape key and overlay click trigger cancel. Used for delete mapping, restore version, discard changes, pause active mapping confirmations.

- **ToastNotificationContainer**: Fixed position (top-right, 20px from edges) container stacking toast notifications. Each toast (350px width, auto height) has colored left border (green success, red error, yellow warning, blue info), icon, title, message, close button, auto-dismiss after 5 seconds with progress bar at bottom. Slide-in animation from right, stack vertically with 10px gap, max 3 visible (oldest dismissed automatically). Click toast to dismiss immediately.

- **LoadingSpinner**: Centered spinner overlay with semi-transparent background during async operations. SVG spinner icon (40px) with rotation animation. Optional loading text below spinner. Blocks all interaction until operation completes.

- **EmptyStateComponent**: Centered content with illustration SVG (200px), heading text, description text, primary action button. Used when mapping list empty, search returns no results, or API errors occur. Different variants for each context with appropriate messaging and CTAs.

## FUNCTIONS

- **initializeApp()**: Entry point - checks localStorage for existing data structure, creates default schema if not found (mappings array, systems config, fieldMetadata cache, versionHistory object), loads saved theme preference, initializes navigation system, attaches global event listeners (window resize, keyboard shortcuts), renders MappingListView as default view, starts background sync status polling at 30-second intervals.

- **renderMappingListView()**: Clears main content container, creates table structure with header row (Name, Source, Target, Direction, Status, Last Sync, Success Rate, Actions), fetches mappings from localStorage sorted by updated_at descending, iterates mappings array calling renderMappingRow for each, attaches search input listener with 300ms debounce calling filterMappings, attaches filter dropdown listeners (status, direction), attaches Create New button click to openMappingWizard, displays empty state if no mappings exist, updates document title to "Sync Mappings".

- **renderMappingRow(mapping, tableBody)**: Creates table row element, populates name cell with clickable link to edit view, adds source object cell with system icon and object name, adds target object cell similarly, creates direction cell with appropriate arrow icon and text (→, ←, ↔), generates status badge (green "Active", yellow "Paused", gray "Draft", red "Error") based on is_active and last_sync_status, formats last_sync_time as relative time (2 hours ago) or "Never", calculates success rate from sync_history array (successful_syncs / total_syncs * 100) with color-coded text (green >90%, yellow 70-90%, red <70%), appends actions cell with icon buttons (Edit, Pause/Resume toggle, Duplicate, Delete), attaches click handlers to each action button, appends row to tableBody.

- **filterMappings(searchTerm, statusFilter, directionFilter)**: Reads all mappings from localStorage, applies search filter checking mapping name, description, source_object, target_object for case-insensitive partial match, applies status filter if not "All" (matches is_active boolean), applies direction filter if not "All" (matches sync_direction value), returns filtered array, updates table body with filtered results, displays "No results found" message if filtered array empty, updates result count text "Showing X of Y mappings".

- **openMappingWizard(mappingId = null)**: Creates wizard modal element (1200px width, 90vh height, centered), builds step indicator sidebar with 8 steps (Basic Info through Review), initializes wizard state object (currentStep: 1, mappingData: {}, validationErrors: {}, isEditMode: mappingId !== null), if mappingId provided loads existing mapping from localStorage into mappingData, renders Step1BasicInfoForm in content area, attaches Next button listener calling validateAndProgressStep, attaches Cancel button listener with unsaved changes check, attaches step indicator click listeners for completed steps allowing direct navigation, appends modal to body, adds show class after 10ms for CSS transition, sets focus on first input field.

- **validateAndProgressStep(wizardState)**: Retrieves current step number from wizardState, calls step-specific validation function (validateStep1, validateStep2, etc.), if validation fails displays inline error messages below invalid fields and returns false, if validation passes clears error messages, saves current step data to wizardState.mappingData, increments currentStep, if currentStep <= 8 renders next step form, if currentStep === 8 calls renderReviewSummary with full mappingData, updates step indicator highlighting current step and marking previous as complete, scrolls wizard content to top, returns true if successful, false if validation failed.

- **validateStep1(formData)**: Extracts name, description, sync_direction from formData, validates name is not empty (error: "Mapping name is required"), validates name length <= 100 chars (error: "Name must be 100 characters or less"), validates name uniqueness against existing mappings excluding current mapping if editing (error: "A mapping with this name already exists"), validates sync_direction is one of valid values (error: "Please select a sync direction"), returns validation result object {isValid: boolean, errors: {fieldName: errorMessage}}.

- **validateStep2(formData)**: Extracts source_system, source_object, target_system, target_object from formData, validates source_object selected (error: "Please select a source object"), validates target_object selected (error: "Please select a target object"), validates source and target are not identical (error: "Source and target objects must be different"), checks for conflicting active mappings on same object pair (error: "An active mapping already exists for these objects"), returns validation result object.

- **validateStep3(formData)**: Extracts field_mappings array from formData, validates at least one field mapped (error: "At least one field mapping is required"), iterates source object required fields checking each is mapped (error: "Required field {fieldName} must be mapped"), validates target object required fields have mappings (error: "Required target field {fieldName} needs a source"), checks for duplicate target field mappings (error: "Target field {fieldName} is mapped multiple times"), validates field type compatibility for each mapping (error: "Cannot map {sourceType} to incompatible {targetType}"), returns validation result object with field-level errors.

- **validateStep4(formData)**: Extracts transformation_rules array from formData, iterates each rule validating transformation_type is valid value, if type is "Formula" validates expression_syntax is not empty (error: "Formula expression is required") and attempts to parse expression checking for syntax errors (error: "Invalid formula syntax: {details}"), if type is "Lookup" validates lookup_object and match_field are selected (error: "Lookup configuration incomplete"), if type is "Custom Function" validates function_code parses as valid JavaScript (error: "Invalid JavaScript code: {details}") and contains required return statement (error: "Custom function must return a value"), tests each transformation with sample data catching runtime errors (error: "Transformation test failed: {details}"), returns validation result object.

- **validateStep5(formData)**: Extracts validation_rules array from formData, iterates each rule validating field_name is selected (error: "Field is required"), validates operator is valid (error: "Operator is required"), if operator requires value validates value_input not empty (error: "Value is required for this operator"), validates regex patterns compile successfully if operator is "regex" (error: "Invalid regex pattern: {details}"), validates error_message provided (error: "Error message is required"), checks for duplicate rules on same field (warning: "Multiple rules exist for {fieldName}"), returns validation result object.

- **validateStep6(formData)**: Extracts conflict_strategy from formData, validates strategy is one of valid options (error: "Please select a conflict resolution strategy"), if strategy is "Custom Logic" validates custom_logic_code is not empty (error: "Custom logic code is required"), validates custom logic parses as valid JavaScript (error: "Invalid JavaScript syntax: {details}"), validates custom logic contains required parameter names (sourceValue, targetValue) in function signature (error: "Custom logic must accept sourceValue and targetValue parameters"), tests custom logic execution with sample data (error: "Custom logic test failed: {details}"), returns validation result object.

- **validateStep7(formData)**: Extracts sync_mode, schedule_config, filter_query from formData, validates sync_mode selected (error: "Please select a sync mode"), if sync_mode is "Real-time" validates polling_interval is number between 1-1440 (error: "Polling interval must be between 1 and 1440 minutes"), if sync_mode is "Scheduled" validates cron_expression matches cron format regex (error: "Invalid cron expression format"), validates cron expression resolves to at least one future execution using cron parser (error: "Cron expression results in no scheduled executions"), if filter_query provided validates SQL WHERE clause syntax (error: "Invalid filter query syntax: {details}"), checks filter references valid field names (error: "Unknown field '{fieldName}' in filter query"), returns validation result object.

- **testMappingConfiguration(mappingData)**: Returns promise, displays loading modal with "Testing mapping configuration...", creates test execution context object, validates field mappings by checking field existence in metadata (step 1/4), executes each transformation rule with sample data collecting results and errors (step 2/4), runs validation rules against transformed data checking pass/fail (step 3/4), simulates conflict scenarios testing conflict resolution strategy (step 4/4), aggregates results into report object {success: boolean, warnings: array, errors: array, details: array}, dismisses loading modal, displays test results modal with success/warning/error counts, expandable details list, returns promise resolving to results object.

- **saveMappingConfiguration(mappingData, activate = false)**: Validates complete configuration calling all validation functions, if validation fails displays error toast and returns false, generates unique ID if new mapping (uuid v4), sets created_at and updated_at timestamps, sets created_by to current user (simulated), sets is_active based on activate parameter, sets version number (increments from existing if edit, 1 if new), if editing creates version history entry capturing previous state, retrieves existing mappings array from localStorage, finds index of existing mapping if editing, replaces existing or appends new to array, saves updated mappings array to localStorage, displays success toast "Mapping saved successfully" or "Mapping created and activated", closes wizard modal, refreshes mapping list view, returns mapping ID.

- **deleteMappingConfiguration(mappingId)**: Retrieves mapping from localStorage by ID, if not found displays error toast and returns, opens confirmation modal with message "Delete mapping '{name}'? This action cannot be undone.", if confirmed performs soft delete by setting deleted_at timestamp and is_deleted flag, updates localStorage, displays success toast "Mapping deleted successfully", removes row from table with fade-out animation, if mapping was active displays warning toast "Active mapping deleted - syncs will stop immediately", returns promise resolving to deleted mapping object.

- **duplicateMappingConfiguration(mappingId)**: Retrieves source mapping from localStorage by ID, creates deep copy of mapping object, generates new unique ID, appends " (Copy)" to name, clears last_sync_time and sync_history, sets is_active to false, sets created_at to current timestamp, saves duplicated mapping to localStorage, displays success toast "Mapping duplicated successfully", refreshes mapping list table, scrolls to and highlights new row, returns new mapping ID.

- **toggleMappingStatus(mappingId)**: Retrieves mapping from localStorage by ID, checks current is_active status, if activating validates configuration is complete and error-free, if pausing active mapping opens confirmation modal "Pause mapping? Active syncs will stop.", toggles is_active boolean, updates updated_at timestamp, saves to localStorage, updates status badge in table row without full page refresh, displays success toast "Mapping {activated/paused} successfully", if activating initiates immediate sync execution, returns new status.

- **renderFieldMappingBuilder(wizardState)**: Creates split-pane layout with source fields container (left), mapping canvas container (center), target fields container (right), fetches source object field metadata from cache or API simulation, fetches target object field metadata similarly, renders source fields list calling renderFieldCard for each field, renders target fields list similarly, initializes mapping canvas with SVG element, if existing field_mappings in wizardState.mappingData iterates and draws connection lines, attaches dragstart listeners to source field cards setting dragged field data, attaches dragover and drop listeners to target field cards for drop-to-map functionality, attaches click listeners for click-to-select mapping mode (click source then target), renders Auto-map button attaching click listener to executeAutoMapping, highlights unmapped required fields with yellow background class, renders mapping legend explaining colors and icons.

- **renderFieldCard(field, container, isSource)**: Creates card div with field name as header, adds field type icon (text icon for string, 123 for number, calendar for date, checkbox for boolean, chain for reference), if field is required adds red asterisk indicator, if field has description adds tooltip on hover showing description, adds draggable attribute and drag handle icon if source field, adds drop zone indicator if target field, adds mapped class if field already in field_mappings array, appends card to container, returns card element reference.

- **drawMappingConnection(sourceFieldCard, targetFieldCard, mappingCanvas)**: Calculates source card position relative to canvas (x1, y1 at right edge, vertically centered), calculates target card position relative to canvas (x2, y2 at left edge, vertically centered), creates SVG path element with cubic bezier curve from (x1, y1) to (x2, y2) with control points for smooth curve, sets stroke color based on mapping status (green if valid, red if error, blue if has transformation), sets stroke width 2px, adds animated dash array for active syncing visualization, creates connection object storing sourceFieldId, targetFieldId, pathElement, adds delete icon at path midpoint with click listener to removeMapping, appends path to canvas SVG, stores connection in mappings array, returns connection object.

- **executeAutoMapping(sourceFields, targetFields, wizardState)**: Iterates source fields attempting to find matching target field by name (case-insensitive, exact match first), if exact match not found tries fuzzy matching removing underscores and comparing, if match found validates field type compatibility, if compatible creates field mapping object {source_field: sourceFieldId, target_field: targetFieldId, transformation_type: "Direct Copy"}, adds to wizardState.mappingData.field_mappings array, draws connection line on canvas, continues for all source fields, displays toast showing auto-map results "Auto-mapped X fields, Y unmapped fields remaining", highlights unmapped required fields, returns count of successfully mapped fields.

- **removeMapping(mappingConnection, wizardState)**: Finds mapping in wizardState.mappingData.field_mappings by source and target field IDs, removes from array, removes SVG path element from canvas with fade-out animation, removes mapped class from source and target field cards, if source or target field is required adds yellow highlight, displays toast "Mapping removed", returns removed mapping object.

- **renderTransformationEditor(fieldMapping, container)**: Creates transformation section with field name header, renders transformation type dropdown with options (Direct Copy, Formula, Lookup, Custom Function), attaches change listener on dropdown to show/hide type-specific editors, if type is Formula renders Monaco-style editor textarea with syntax highlighting (pattern-based, highlights ${fieldName} references, operators, function names), adds formula helper dropdown showing available functions (UPPER, LOWER, CONCAT, SUBSTRING, DATE_FORMAT, etc.) with insert button, if type is Lookup renders object selector dropdown and match field selector, if type is Custom Function renders code editor textarea with JavaScript syntax highlighting, adds sample code template button, renders Test Transformation button opening test modal, in test modal creates input field for sample data, Execute Test button runs transformation logic in isolated context catching errors, displays output or error message with syntax highlighting, appends complete section to container.

- **executeTransformation(transformationType, config, inputValue)**: Creates isolated execution context, if type is "Direct Copy" returns inputValue unchanged, if type is "Formula" parses expression extracting field references and functions, evaluates expression with inputValue substituted for field references, executes formula functions (UPPER converts to uppercase, CONCAT joins strings, DATE_FORMAT formats dates), returns computed result or throws error with details, if type is "Lookup" simulates lookup query against target object returning matched record value or null, if type is "Custom Function" wraps function code in try-catch, creates function with parameters (value, context), executes function passing inputValue, returns function result or throws error, logs execution details for debugging.

- **renderValidationRuleBuilder(wizardState)**: Creates validation rules section header with Add Rule button, if existing validation_rules in wizardState.mappingData iterates calling renderValidationRuleRow for each, attaches Add Rule button click to create new empty rule and render row, appends section to wizard content area, returns rule count.

- **renderValidationRuleRow(rule, ruleIndex, container)**: Creates rule row div with grid layout (4 columns), renders field selector dropdown populated with mapped fields only, attaches change listener updating rule.field_name, renders operator dropdown with all operator options (equals, not equals, contains, starts with, ends with, regex, greater than, less than, is empty, is not empty), attaches change listener updating rule.operator and showing/hiding value input based on operator, renders value input text field (number input if field type is numeric), attaches input listener updating rule.value with validation, renders error message textarea for custom error text, attaches input listener updating rule.error_message, renders Delete Rule icon button attaching click listener to remove rule from array and remove row from DOM, appends row to container, returns row element.

- **validateFieldValue(value, operator, compareValue, fieldType)**: Coerces value to appropriate type based on fieldType (string, number, date, boolean), executes operator logic: equals checks strict equality, not equals checks inequality, contains checks string includes compareValue, starts with checks string prefix, ends with checks string suffix, regex creates RegExp from compareValue and tests value, greater than / less than performs numeric/date comparison, is empty checks for null/undefined/empty string, is not empty checks opposite, returns boolean result, throws error if operator invalid or type coercion fails.

- **renderConflictResolutionForm(wizardState)**: Creates conflict strategy section, renders radio button group with 5 options in vertical layout, each radio has label text, description paragraph explaining behavior, attaches change listener updating wizardState.mappingData.conflict_strategy, if Custom Logic selected shows code editor textarea, renders editor with custom logic template (function(sourceValue, targetValue, sourceTimestamp, targetTimestamp, fieldName) { return sourceValue; }), attaches input listener updating wizardState.mappingData.custom_logic_code, adds Test Logic button opening test modal with sample conflict scenario inputs, appends section to wizard content area.

- **resolveConflict(strategy, sourceValue, targetValue, context)**: Executes conflict resolution based on strategy parameter, if "Source Wins" returns sourceValue, if "Target Wins" returns targetValue, if "Most Recent Wins" compares context.sourceTimestamp and context.targetTimestamp returning value from most recent, if "Manual Review Required" returns special flag object {requiresReview: true, sourceValue, targetValue} for queue, if "Custom Logic" evaluates context.custom_logic_code function passing all parameters returning function result, validates return value is defined and not null (error: "Conflict resolution must return a value"), logs resolution decision with context for audit trail, returns resolved value.

- **renderSyncScheduleForm(wizardState)**: Creates sync schedule section,
