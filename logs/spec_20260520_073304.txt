# TECHNICAL SPECIFICATION: Real-time Sync Execution Engine

## OVERVIEW

A comprehensive synchronization engine that orchestrates bidirectional data synchronization between Salesforce and external systems. The engine implements polling-based change detection, transformation pipeline execution, conflict resolution, validation, retry mechanisms, and comprehensive audit logging. Built as a distributed system with background workers processing queued sync jobs, REST API endpoints for manual triggering and monitoring, and database-backed state persistence ensuring reliability and observability.

## VIEWS

- SyncExecutionDashboard: Main monitoring view displaying active syncs, recent history, success/failure metrics, and health indicators with real-time status updates via polling or WebSocket
- SyncHistoryTable: Paginated table view showing past sync executions with filters for date range, mapping ID, status, and search by record ID
- SyncDetailView: Drill-down view for individual sync execution showing records processed, field-level changes, errors, conflicts resolved, and timeline of events
- SyncLogViewer: Detailed log browser with filtering by severity, field name, record ID, and full-text search across error messages
- SyncHealthMonitor: Dashboard displaying sync health metrics including consecutive failure counts, average execution time, success rate trends, and alert configuration
- ConflictResolutionQueue: Interface for reviewing and manually resolving sync conflicts flagged for manual review, showing side-by-side comparison of conflicting values
- SyncSettingsPanel: Configuration interface for polling intervals, retry policies, conflict resolution strategies, and webhook notification settings

## FUNCTIONS

- initializeSyncEngine(): Bootstrap the sync engine on application startup, load configurations from database, initialize connection pools to Salesforce API and destination systems, start background worker threads, register signal handlers for graceful shutdown
- startPollingCycle(mappingId, interval): Create scheduled job for specific mapping that triggers at configured interval, calculate next run time based on interval setting, persist schedule in database, handle interval changes dynamically
- pollSalesforceChanges(mappingId, lastSyncTimestamp): Query Salesforce API for records modified since last sync timestamp using SOQL WHERE LastModifiedDate > lastSyncTimestamp, handle API pagination with nextRecordsUrl, extract changed records with all mapped fields, return array of changed record objects with metadata
- pollDestinationChanges(mappingId, lastSyncTimestamp): Query destination system API for changes since last sync for bidirectional mappings, normalize response format to internal structure, handle pagination and rate limiting, return array of changed records
- detectChanges(sourceRecords, destinationRecords, mapping): Compare source and destination record sets to identify creates, updates, deletes, calculate field-level diffs for each record, detect bidirectional conflicts where both sides changed, return change set object with categorized operations
- createSyncExecution(mappingId, triggeredBy, triggerType): Insert new record into sync_executions table with status 'pending', generate unique execution ID, record triggered_by user or system, set trigger_type as 'scheduled', 'manual', or 'webhook', initialize counters to zero, return execution object
- enqueueSyncJob(executionId, changeSet): Serialize change set and execution context, push job message to sync queue with priority based on mapping configuration, set job timeout and retry policy, emit job_enqueued event, return queue position
- processSyncQueue(): Background worker main loop that polls sync queue for pending jobs, acquires distributed lock on job to prevent duplicate processing, deserializes job payload, calls executeSyncJob, handles worker health checks, implements graceful shutdown on SIGTERM
- executeSyncJob(executionId, changeSet, mapping): Main sync orchestration function that updates execution status to 'running', iterates through change set operations, calls processRecord for each record, aggregates results, handles transaction boundaries, updates final execution statistics, sets status to 'completed' or 'failed'
- processRecord(record, operation, mapping, executionId): Process single record through full sync pipeline, call transformRecord, validateRecord, resolveConflicts, writeToDestination in sequence, create sync_log entries for each field change, handle record-level errors with try-catch, increment execution counters
- transformRecord(record, mapping): Apply transformation pipeline from mapping configuration, iterate through field mappings, call appropriate transformation function based on type, handle transformation errors with fallback to original value, return transformed record object
- applyDirectCopy(sourceValue, fieldMapping): Extract value from source field path, handle nested object navigation with dot notation, perform type coercion if needed, return transformed value
- applyStringFormat(sourceValue, formatTemplate, fieldMapping): Parse format template with placeholder syntax like ${field1} ${field2}, replace placeholders with source values, handle null/undefined values with empty string or configured default, apply string functions like uppercase/lowercase/trim, return formatted string
- applyDateConversion(sourceValue, sourceFormat, targetFormat, fieldMapping): Parse source date string using sourceFormat pattern, handle timezone conversions based on mapping configuration, format to target format, handle invalid dates with error or null, return formatted date string or ISO timestamp
- applyLookupResolution(sourceValue, lookupConfig, fieldMapping): Query lookup table or API with source value as key, cache lookup results with TTL to minimize API calls, handle lookup failures with configured fallback value or error, support multi-field composite lookups, return resolved value or original if not found
- applyFormulaCalculation(record, formulaExpression, fieldMapping): Parse formula expression using expression evaluator library, resolve field references in formula from record object, handle arithmetic operators, string concatenation, conditional logic, execute formula in sandboxed environment, catch evaluation errors, return calculated value
- validateRecord(transformedRecord, destinationSchema, validationRules): Check required fields are present and non-null, validate data types match schema definitions, enforce field length constraints, apply custom validation rules from configuration, collect all validation errors into array, return validation result object with isValid boolean and errors array
- detectConflict(sourceRecord, destinationRecord, mapping): Compare LastModifiedDate or version timestamps from both sides, identify fields that changed on both sides since last sync, calculate conflict severity based on field importance, return conflict object with conflicting fields and timestamps
- resolveConflict(conflict, strategy, executionId): Apply conflict resolution strategy from mapping configuration, for 'source_wins' take source value, for 'destination_wins' take destination value, for 'most_recent' compare timestamps and take newer, for 'manual_review' enqueue to conflict resolution queue, log resolution decision, return resolved record
- writeToDestination(record, operation, destinationConfig): Determine destination API endpoint based on operation type (create/update/delete), construct API request with proper authentication headers, serialize record to destination format, send HTTP request with retry on transient failures, parse response for success/error, return write result object
- handleWriteError(error, record, executionId, attempt): Log error details to sync_logs table, categorize error as transient or permanent based on error code, for transient errors enqueue retry job with exponential backoff, increment attempt counter, for permanent errors mark as failed, emit error event for monitoring, create alert if threshold exceeded
- retryFailedSync(executionId, record, attempt): Calculate backoff delay as min(baseDelay * 2^attempt, maxDelay), schedule retry job for execution after backoff period, update record status to 'retrying', increment attempt counter, check if max attempts exceeded and mark as permanently failed, log retry attempt
- createSyncLog(executionId, recordId, fieldName, oldValue, newValue, errorMessage, level): Insert detailed log entry into sync_logs table with timestamp, normalize values to string for storage, set log level as 'info', 'warning', 'error', include execution context, enable full-text search on error messages, return log ID
- updateExecutionStatistics(executionId, recordsProcessed, recordsSucceeded, recordsFailed, fieldsUpdated, conflictsResolved): Increment counters in sync_executions table using atomic update operations, calculate duration from started_at to current time, update status based on success/failure counts, persist statistics for reporting
- checkSyncHealth(mappingId): Query recent sync executions for mapping, calculate success rate over last 24 hours, identify consecutive failures, check average execution duration for degradation, evaluate error patterns, return health status object with metrics and recommendations
- generateHealthAlert(mappingId, alertType, severity, message): Create alert record in sync_alerts table, check alert throttling to prevent spam, send notifications via configured channels (email, Slack, webhook), include health metrics and suggested actions, mark similar recent alerts as consolidated
- getSyncStatus(executionId): Query sync_executions table for current status, calculate percentage complete based on records processed vs total, estimate remaining time based on current rate, include recent log entries, return status object for API response
- getSyncHistory(filters, pagination): Query sync_executions table with filters for mapping_id, status, date range, apply pagination with offset and limit, join with mapping configuration for display names, order by started_at descending, return paginated result set with total count
- triggerManualSync(mappingId, userId, options): Validate mapping exists and is active, create sync execution with trigger_type 'manual' and triggered_by user ID, override polling to fetch all changes since last sync or from specified timestamp, enqueue sync job with high priority, return execution ID for status polling
- cancelSyncExecution(executionId, userId): Update execution status to 'cancelled' if still pending or running, set cancelled_by and cancelled_at fields, remove job from queue if not yet started, stop worker processing if in progress, log cancellation action, return cancellation result
- exportSyncLogs(executionId, format): Query sync_logs for execution with all details, format as CSV or JSON based on request, include field-level changes and error messages, stream large result sets to avoid memory issues, return file download or S3 URL
- archiveOldSyncData(retentionDays): Identify sync_executions and sync_logs older than retention period, move to archive tables or cold storage, maintain summary statistics, delete archived records from active tables, log archival operation
- loadMappingConfiguration(mappingId): Query field_mappings table with all transformation rules, load conflict resolution strategy, fetch polling interval and enabled status, load validation rules and schemas, cache configuration with TTL, return full mapping config object
- updateMappingLastSync(mappingId, timestamp): Update last_sync_timestamp in field_mappings table to track successful sync completion, use timestamp for next incremental sync query, handle race conditions with optimistic locking
- getActiveWorkerCount(): Query worker registry or health check endpoint, count workers with recent heartbeat, identify stale workers for cleanup, return active worker count for monitoring
- registerWorker(workerId, hostname, pid): Insert worker record into worker_registry table, set heartbeat timestamp, record process details, enable worker discovery and coordination
- updateWorkerHeartbeat(workerId): Update heartbeat timestamp atomically, include current job info, mark worker as healthy, enable detection of crashed workers
- acquireJobLock(jobId, workerId, lockTimeout): Attempt to acquire distributed lock on job using database row lock or Redis lock, set lock owner to workerId, set lock expiration, return lock acquisition result
- releaseJobLock(jobId, workerId): Release distributed lock on job, verify lock owner matches workerId, delete lock record, allow other workers to process job
- handleWorkerShutdown(): Gracefully shutdown worker on SIGTERM signal, finish processing current job if possible or release lock for retry, update worker status to 'stopped', close database connections, flush logs, exit process cleanly

## DATA

- sync_executions: Stores sync execution metadata including id (UUID primary key), mapping_id (foreign key to field_mappings), status (enum: pending, running, completed, failed, cancelled), triggered_by (user ID or 'system'), trigger_type (enum: scheduled, manual, webhook), started_at (timestamp), completed_at (timestamp), records_processed (integer counter), records_succeeded (integer), records_failed (integer), fields_updated (integer), conflicts_resolved (integer), errors_count (integer), duration_ms (integer), error_summary (text), created_at (timestamp), indexes on mapping_id, status, started_at for query performance
- sync_logs: Stores field-level change details including id (bigint auto-increment), execution_id (foreign key to sync_executions), record_id (string identifier in source/destination system), record_type (string entity name), field_name (string), old_value (text), new_value (text), transformation_applied (string transformation type), error_message (text), error_code (string), level (enum: info, warning, error), timestamp (timestamp with millisecond precision), indexes on execution_id, record_id, level, full-text index on error_message
- sync_queue: Transient job queue including job_id (UUID), execution_id (foreign key), mapping_id (foreign key), priority (integer), payload (JSONB with change set), status (enum: queued, processing, completed, failed), attempt_count (integer), max_attempts (integer default 3), next_retry_at (timestamp), created_at (timestamp), claimed_by (worker ID), claimed_at (timestamp), indexes on status, priority, next_retry_at for efficient worker polling
- conflict_resolutions: Stores manual conflict resolution queue including id (UUID), execution_id (foreign key), record_id (string), field_name (string), source_value (text), destination_value (text), source_timestamp (timestamp), destination_timestamp (timestamp), status (enum: pending, resolved, skipped), resolved_by (user ID), resolved_at (timestamp), resolution_choice (enum: source, destination, custom), custom_value (text), notes (text), created_at (timestamp), indexes on status, execution_id
- sync_alerts: Stores health monitoring alerts including id (UUID), mapping_id (foreign key), alert_type (enum: consecutive_failures, high_error_rate, performance_degradation, data_quality), severity (enum: info, warning, critical), message (text), metrics (JSONB with health data), status (enum: active, acknowledged, resolved), created_at (timestamp), acknowledged_by (user ID), acknowledged_at (timestamp), resolved_at (timestamp), indexes on mapping_id, status, created_at
- worker_registry: Tracks active background workers including worker_id (UUID), hostname (string), process_id (integer), status (enum: active, idle, stopped), last_heartbeat (timestamp), current_job_id (UUID nullable), jobs_completed (integer counter), started_at (timestamp), indexes on status, last_heartbeat for health checks
- mapping_configs_cache: In-memory cache storing parsed mapping configurations with mapping_id as key, configuration object with all transformation rules as value, TTL of 300 seconds, invalidated on mapping updates
- lookup_cache: In-memory cache for lookup resolutions with composite key (lookup_table, lookup_key) and resolved value, TTL configurable per lookup (default 3600 seconds), implements LRU eviction policy
- sync_execution_status: In-memory map tracking real-time status of running syncs with execution_id as key, status object with percentage complete, current record, start time as value, used for /sync/status API responses

## API

- POST /api/sync/execute: Triggers manual sync execution accepting JSON payload {mapping_id: string, options: {full_sync: boolean, since_timestamp: ISO8601 string}}, validates mapping_id exists and is active, creates sync execution, enqueues job, returns {execution_id: string, status: string, message: string}, handles 404 for invalid mapping, 400 for validation errors, 429 for rate limiting
- GET /api/sync/status/:executionId: Retrieves current status of sync execution, queries sync_executions table and in-memory status map, calculates percentage complete, includes recent errors, returns {execution_id: string, status: string, progress: {records_processed: int, total_records: int, percentage: float}, started_at: ISO8601, estimated_completion: ISO8601, recent_logs: array}, handles 404 for unknown execution_id
- GET /api/sync/history: Lists past sync executions with pagination, accepts query params mapping_id, status, since, until, page, page_size, orders by started_at descending, returns {executions: array, pagination: {page: int, page_size: int, total_count: int, total_pages: int}}, handles invalid date formats with 400 error
- GET /api/sync/logs/:executionId: Retrieves detailed logs for execution, accepts query params level, field_name, record_id, page, page_size, applies filters, returns {logs: array of log objects, pagination: object}, handles 404 for unknown execution
- POST /api/sync/cancel/:executionId: Cancels running or pending sync, validates user has permission, updates execution status, removes from queue or signals worker, returns {execution_id: string, status: string, cancelled_at: ISO8601}, handles 404, 403 forbidden, 409 conflict if already completed
- GET /api/sync/health/:mappingId: Returns health metrics for mapping, calculates success rate, consecutive failures, average duration, error patterns, returns {mapping_id: string, health_status: string, metrics: {success_rate: float, consecutive_failures: int, avg_duration_ms: int, last_success: ISO8601}, alerts: array}, handles 404
- GET /api/sync/conflicts: Lists pending conflict resolutions, accepts query params mapping_id, page, page_size, returns {conflicts: array with source/dest values and timestamps, pagination: object}
- POST /api/sync/conflicts/:conflictId/resolve: Resolves manual conflict, accepts JSON {resolution_choice: string, custom_value: optional string, notes: optional string}, validates choice, updates record, triggers retry of affected sync operation, returns {conflict_id: string, status: string}, handles 404, 400 for invalid choice
- GET /api/sync/metrics: Returns aggregate metrics across all syncs, accepts query params since, until, mapping_id for filtering, calculates total syncs, success rate, total records processed, average duration, returns {period: {since: ISO8601, until: ISO8601}, metrics: {total_syncs: int, success_rate: float, total_records: int, avg_duration_ms: int, active_syncs: int}}
- POST /api/sync/mappings/:mappingId/poll-now: Forces immediate polling check bypassing schedule, creates execution if changes detected, returns {changes_detected: boolean, execution_id: optional string, next_scheduled_poll: ISO8601}
- GET /api/sync/workers: Returns status of background workers, lists all workers with heartbeat status, current jobs, completion stats, returns {workers: array of worker objects, total: int, active: int, idle: int}, requires admin role
- POST /api/sync/workers/:workerId/shutdown: Gracefully shuts down specific worker, signals worker to finish current job and exit, returns {worker_id: string, status: string, shutdown_initiated_at: ISO8601}, requires admin role, handles 404

## ERRORS

- MappingNotFoundError: Thrown when mapping_id does not exist in database, return 404 status with message "Mapping configuration not found", log error with mapping_id, suggest checking mapping exists and is not deleted
- MappingDisabledError: Thrown when attempting to sync disabled mapping, return 400 status with message "Mapping is currently disabled", include mapping name and last disabled timestamp, suggest enabling mapping in configuration
- SalesforceAPIError: Thrown when Salesforce API returns error response, capture error code, message, and HTTP status from API, return 502 Bad Gateway with details, handle rate limit errors (429) with retry-after header, handle authentication errors (401) with re-auth trigger, log full API response for debugging
- DestinationAPIError: Thrown when destination system API fails, capture error details, categorize as transient (timeout, 5xx) or permanent (400, 404), return 502 status, schedule retry for transient errors, log error with full context
- TransformationError: Thrown when field transformation fails, capture field name, transformation type, source value, error message from transformation function, mark record as failed, continue processing other records, log error with transformation config details
- ValidationError: Thrown when transformed record fails validation, collect all validation failures (missing required fields, type mismatches, constraint violations), mark record as failed with validation details in sync_logs, return 400 for API validation errors, log each validation failure separately
- ConflictDetectionError: Thrown when unable to determine conflict due to missing timestamps or corrupted data, mark record for manual review, log error with both source and destination records, alert administrator
- LockAcquisitionTimeout: Thrown when worker cannot acquire job lock within timeout period, indicates another worker processing same job or stale lock, log warning, requeue job for retry, investigate if repeated frequently
- DatabaseConnectionError: Thrown when database connection fails during sync operation, retry query with exponential backoff, pause worker if connection persistently fails, alert operations team, log connection error details
- QueueFullError: Thrown when sync queue exceeds maximum size, return 503 Service Unavailable, suggest retrying later, trigger alert for queue backlog, log queue size and oldest job age
- MaxRetriesExceededError: Thrown when record sync fails after max retry attempts, mark record as permanently failed, create high-priority alert, log full error history across all attempts, move to dead letter queue for manual intervention
- WorkerCrashError: Detected when worker heartbeat times out, log worker crash with last known job, mark in-progress jobs as failed, restart worker automatically, alert if crashes frequent
- DataTypeConversionError: Thrown when converting value between source and destination types fails, capture source value, source type, target type, conversion error, skip field update or use default value based on config, log error with field mapping details
- CircularDependencyError: Thrown when formula fields reference each other creating cycle, detect during transformation planning phase, return 400 with dependency graph, log circular fields, require configuration fix
- SchemaValidationError: Thrown when destination schema rules not met, capture schema definition, record values, specific constraint violations, mark record as failed, log with
