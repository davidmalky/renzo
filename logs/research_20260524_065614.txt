## RISKS:

### Technical Risks
1. **Regex edge cases**: The regex `/\{[\s\S]*\}/` is greedy and will match the first `{` to the last `}` in the entire string. If Claude returns text before or after the JSON, this is robust. If Claude returns multiple JSON objects, only the outer one will be captured.

2. **JSON.parse() failures**: Even with regex extraction, malformed JSON will still throw. The existing try-catch blocks should handle this, but the new code adds specific error paths.

3. **Empty responses**: If `data.content[0].text` is empty or only whitespace, `jsonMatch` will be null. The code handles this with the `if(!jsonMatch)` check.

4. **Case sensitivity**: The regex uses `/i` flag for case-insensitive matching of "json" marker, which is more robust than current code.

### Breaking Changes
- **NONE**: Changes are internal to `runBatch()`, no function signatures or external interfaces change
- Existing code calling `runBatch()` requires no modifications
- localStorage data structures remain unchanged
