## RISKS:

### Technical Conflicts
1. **Fixed Positioning Overlap**: Mobile header (top: 0) + bottom nav (bottom: 0) + main content scrolling could cause z-index conflicts
2. **Content Visibility**: .main padding-top/bottom must account for exact header/nav heights (52px + 64px = 116px total lost viewport)
3. **Navigation State Management**: Active nav item border change (left→top) requires ensuring JavaScript doesn't break when applying `.active` class
4. **Table to Card Switch**: If `renderContacts()` is called frequently, performance could degrade on resize events
5. **Modal Z-Index**: Modals must appear above bottom nav (z-index > 500)

### Layout Issues
1. **Viewport Height on Mobile**: 100vh issues on iOS Safari (address bar causes reflow)
2. **Bottom Nav Safe Area**: Need to account for iOS home indicator (safe-area-inset-bottom)
3. **Scrolling**: Ensure .main scrolls properly with fixed header/footer
4. **Touch Targets**: All interactive elements need 44px+ hit area verification
5. **Horizontal Overflow**: Bottom nav with 8 items at flex:1 might cause text truncation

### Data & Rendering Risks
1. **Contacts Rendering Logic**: Must preserve existing filter/sort/pagination if present
2. **Card Data Mapping**: Need exact field names (name, priority, company, tier, status) from data structure
3. **Button Actions**: Message button in cards must hook into existing message/draft system
4. **State Persistence**: Active view must persist across layout changes
5. **Real-time Updates**: If contacts update live, card rendering must handle updates

### Responsive Breakpoint Issues
1. **768px Breakpoint**: Common tablet width - may need to test iPad portrait/landscape
2. **Orientation Changes**: Need to handle landscape mobile (short height)
3. **Font Scaling**: 10px font in bottom nav may be too small on some devices
4. **Icon Size**: Need to verify emoji rendering across platforms (iOS vs Android)
