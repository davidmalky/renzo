## RISKS

### Technical Risks:

1. **AbortSignal Browser Compatibility**
   - `AbortSignal.timeout()` is modern API (2022+)
   - Risk: May not work in older browsers
   - Mitigation: Assumes modern browser target (no polyfill mentioned in task)

2. **Multiple Abort Sources**
   - If code already uses AbortController elsewhere, adding timeout could conflict
   - Risk: Existing abort logic might be overridden
   - Mitigation: Task states these are additions, implying no existing abort logic

3. **Button Reference Validity**
   - Catch blocks must re-enable correct button
   - Risk: Button variable might be out of scope in catch block
   - Mitigation: Verify each function's button reference pattern

4. **aiLoading Element in generateMsg()**
   - Must ensure element exists before accessing
   - Risk: `getElementById('aiLoading')` could be null
   - Mitigation: Existing code presumably already uses this element safely

5. **Error Message Consistency**
   - Toast messages must match exact specification
   - Risk: Typos or variations in error messages
   - Mitigation: Use exact strings: "Request timed out — try again" and "Error: " + e.message

6. **Success Path Button Re-enable**
   - Task emphasizes "both success and error paths"
   - Risk: Success path might already handle this, adding duplicate code
   - Mitigation: Review each function's success callback/then block

7. **Service Worker Fetch (sReadWebsite)**
   - Service worker context has different error handling needs
   - Risk: Toast notifications might not work in service worker
   - Mitigation: May need different error handling strategy for this listener
