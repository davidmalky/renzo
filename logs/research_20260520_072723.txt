## RISKS:

### Technical Conflicts
1. **Client-side vs Server-side Architecture**: Current HTML is pure client-side, but sync engine requires server-side components (Node.js/Express for API endpoints, database connections)
   - Risk: Complete architectural mismatch between static HTML and required backend services
   - Mitigation needed: Clear separation of frontend (existing HTML) and backend (new Node.js service)

2. **Database Storage**: Task requires SQL database tables (sync_executions, sync_logs), but existing code has no database layer
   - Risk: Need to introduce ORM (Sequelize, TypeORM) or query builder (Knex)
   - Conflict: localStorage mentioned in CSP, but not used; need clarification on storage strategy

3. **Real-time Polling**: Continuous polling can conflict with browser tab sleep/background throttling
   - Risk: Missed sync intervals when tab inactive
   - Mitigation: Use Service Workers or Web Workers for background processing

4. **API Rate Limiting**: Salesforce API has strict rate limits
   - Risk: Polling too frequently causes 429 errors
   - Mitigation: Implement request throttling and exponential backoff

### Data Consistency Risks
5. **Bidirectional Sync Conflicts**: Two-way sync can create infinite loops
   - Risk: Record A updates B, B updates A, repeat
   - Mitigation: Change tracking with timestamps and sync version numbers

6. **Concurrent Sync Executions**: Multiple sync jobs running simultaneously
   - Risk: Race conditions, duplicate processing
   - Mitigation: Job queue with locking mechanism

7. **Transformation Failures**: Formula calculations may fail on invalid data
   - Risk: Sync halts mid-process leaving inconsistent state
   - Mitigation: Transaction-based sync with rollback capability

### Performance Risks
8. **Large Dataset Sync**: Processing thousands of records
   - Risk: Browser memory limits, UI freezing
   - Mitigation: Batch processing with progress indicators

9. **Log Storage Growth**: Detailed logs for every field change
   - Risk: Database bloat, slow queries
   - Mitigation: Log rotation, archival strategy, indexed queries

### Security Risks
10. **Salesforce OAuth Tokens**: Storing sensitive credentials
    - Risk: Token exposure in client-side code
    - Mitigation: Server-side token storage, secure cookie handling

11. **API Endpoint Security**: New REST endpoints exposed
    - Risk: Unauthorized access to sync operations
    - Mitigation: JWT authentication, role-based access control

### Integration Risks
12. **Existing UI State Management**: No visible state management framework (React, Vue, Svelte)
    - Risk: Complex sync state difficult to manage with vanilla JS
    - Mitigation: May need to introduce lightweight state management

13. **Schema Changes**: Salesforce schema evolution over time
    - Risk: Mappings become invalid when fields change
    - Mitigation: Schema validation on each sync, mapping health checks

#### Database Tables (PostgreSQL/MySQL format):
```sql
-- sync_executions table
{
  id: UUID PRIMARY KEY,
  mapping_id: UUID FOREIGN KEY,
  status: ENUM('queued', 'running', 'completed', 'failed', 'retrying'),
  started_at: TIMESTAMP,
  completed_at: TIMESTAMP,
  records_processed: INTEGER,
  errors_count: INTEGER,
  retry_count: INTEGER DEFAULT 0,
  config_snapshot: JSONB, -- Mapping config at execution time
  created_at: TIMESTAMP,
  updated_at: TIMESTAMP
}

-- sync_logs table
{
  id: UUID PRIMARY KEY,
  execution_id: UUID FOREIGN KEY,
  record_id: STRING, -- Salesforce record ID
  record_type: STRING, -- Object type (Account, Contact, etc.)
  field_name: STRING,
  old_value: TEXT,
  new_value: TEXT,
  transformation_applied: STRING,
  error_message: TEXT,
  conflict_resolution: ENUM('source_wins', 'destination_wins', 'manual', 'timestamp'),
  timestamp: TIMESTAMP,
  created_at: TIMESTAMP
}

-- sync_queue table (for retry management)
{
  id: UUID PRIMARY KEY,
  execution_id: UUID FOREIGN KEY,
  payload: JSONB, -- Record data to sync
  retry_count: INTEGER DEFAULT 0,
  next_retry_at: TIMESTAMP,
  last_error: TEXT,
  created_at: TIMESTAMP,
  updated_at: TIMESTAMP
}
```
